# Pi 自动路由优化与验证

作者：Jeff.Liu

日期：2026-11-01

参考方案、审查结论与后续阶段见 [参考与后续路线](pi-routing-references.md)。本文描述当前源码；10 月 27 日的历史报告仅证明当时版本，不能替代本轮订阅直连验收。

## 使用方式

- 在新会话配置的「Pi 自动路由 → 任务规则」中编辑任务描述、示例、模型角色和自动推理档位，点击「应用任务规则」后再保存会话默认设置。
- 运行中会话通过「调整路由 → 任务规则」修改。执行期间禁用修改；保存前检查状态版本，避免覆盖更新后的配置。
- 「恢复默认任务规则」只修改编辑草稿，点击应用才生效。「取消规则修改」重新载入已保存版本。
- 会话中的「试判任务规则」只发送输入框文本和候选规则给分类模型，不执行任务、不改变模型偏好、不保存试判文本；调用可能产生费用。试判不带当前对话，因此短追问会缺少上下文。输出是规则候选，实际运行还会应用固定选择、继续任务约束、容量和缓存判断。
- 新会话默认通过 `--yam-rules '<JSON>'` 随现有启动设置保存。原生会话记录自己的 `yam.routing.rules.v1` 快照；恢复、切换历史分支时使用该分支保存的规则，不用新的启动默认覆盖。没有旧快照的分支在首次读取时保存一份。
- 损坏或非法的已保存规则会停止推理；可从会话规则编辑器应用有效规则恢复。切换模型或重置偏好不能绕过非法规则。规则编辑不会修复模型连接或不支持的固定推理档位。

## 路由行为

分类模型提取任务类型、上下文依赖、操作需求、分析深度、新任务/继续关系、不确定状态与只读属性。分类结果没有选择任意模型或授予工具权限的能力；这些字段是语义预测，不是安全证明。

| 类型 | 默认角色 | 自动推理目标 |
| --- | --- | --- |
| 翻译与整理 `transform` | 轻量 | medium |
| 独立问答 `answer` | 轻量 | medium |
| 仓库理解 `repository` | 强 | high |
| 编码与调试 `coding` | 强 | high |
| 深入审查 `review` | 强 | high |
| 其他 `other` | 强 | high |

仅独立、上下文充分且无工具/外部操作需求的翻译整理和问答可自动使用轻量角色。其他类型有强模型保护下限，深入分析默认 high；用户可显式选择更高档位。可将简单任务改用强模型或提高档位；规则不能关闭这些保护。

规则固定六类，不支持脚本和任意执行条件。每类描述最多 600 字符、示例最多四条且每条 160 字符，整份配置最多 6000 UTF-8 字节。全部字段、版本和类型均校验，重复/缺失类别及未知字段拒绝。回退策略必须为强模型 high 或以上。版本是规范化配置的展示标识，不用于安全认证或并发控制；并发使用原有递增 revision。

普通 API 分类响应无效、超时、旧格式、未知类别、不确定或上下文不足时保守使用强模型；订阅分类失败或配置的分类连接不可用时明确停止，避免跨通道回退，并保留继续任务的既有下限。即使不确定，只要识别为深入分析也使用审查规则指定的强模型档位（默认 high）。同一任务可以升档，不能自动降档；明确的新任务允许重新选择。轮内工具调用、重试复用已有模型。

用户固定模型和推理档位继续独立生效。两者均固定时不分类；只固定模型、推理自动时仍分类。固定档位不支持时停止而不静默降级。

普通 API 分类最长等待 15 秒，ChatGPT 订阅分类最长等待 45 秒；输出上限由 1024 缩为 512 tokens，仍使用 medium 或向上映射的受支持档位。输入为当前请求（超过 16000 字符直接保守回退）、原生任务摘要和最近六条截断摘要。分类载荷显式标记摘要截断；不进行关键词直接放行，也不调用工具调查仓库。

保留现有一次回复修正：只有合格的独立只读任务、实际尚未使用工具、没有固定模型，且回复空白、截断或明确表示能力不足时才能尝试强模型。修正请求禁用工具；失败保留原回复，取消时标记中断。流畅但错误的回答不在此检测能力内。语义评审重答和多模型 Critique 未启用。

## 费用与记录

公开状态及 `yam.routing.decision.v1` 只保存规则/版本、计划和实际角色、分类耗时、缓存保留、修正状态及费用，不复制请求或分类理由。原生会话已有任务摘要仍按原逻辑保存，不新建对话采集器。

分类、原生执行（包括工具循环中的模型回复）、修正费用分开累计。仅有可确认的价格和完整 `usage.cost` 分项时采用模型报告的费用；缺任一部分时相应项与总费用为未知。格式非法但有明确用量的分类响应仍计费。界面显示「截至当前」的费用，不把尚未完成的轮次当最终账单。账单、超时期间的服务端用量仍以提供方为准。

## 离线评测

```sh
node scripts/pi-routing-eval.mjs cases.json observations.json
```

用例是数组，每条含唯一 `id` 和 `expected: {model: "small|strong", effort: "medium|high|..."}`。观察必须逐一匹配所有用例，含 `id`、实际角色、档位和非负 `latencyMs`；可选 `totalCost` 为包含分类、执行、评审和补救的全链费用，可选 `taskPassed` 为最终任务验收结果。缺失、重复、多余或非法观察拒绝生成报告。

分别统计准确匹配、降档不足、额外升档和平均延迟。模型/推理为两个维度，降档与升档计数可能同时出现。费用或任务质量不完整时，对应指标保持 null；没有通过任务时，每个通过任务的费用也为 null。该命令不会发起模型调用或执行用例。

`apps/desktop/tests/fixtures/pi-routing-cases.json` 的 32 条用例是设计阶段合成样本，预期标签与测试使用的任务事实由人工编写，不能作为真实业务质量证明。默认规则在已给定正确任务事实时匹配这 32 条预期，只验证策略映射。

## 本次真实分类对比

通过本机已有网关 Responses 接口，对同一批 32 条合成请求分别调用旧/新提示词。模型均为 `codex/gpt-6-luna`、medium；旧输出上限 1024，新为 512，均限制 15 秒。每条新旧请求同时发送，顺序遍历用例；只分类，不执行任务、不发送项目对话或代码。

| 指标 | 改造前提示词 + 旧策略 | 新提示词 + 新策略 |
| --- | ---: | ---: |
| 与设计预期完全一致 | 25/32 | 29/32 |
| 降档不足 | 5 | 0 |
| 额外升档 | 2 | 3 |
| 平均分类耗时（含超时） | 4525.91 ms | 5026.81 ms |
| 客户端超时 | 2 | 2 |
| 完整分类费用 | 未知 | 未知 |
| 最终任务通过率 | 未评测 | 未评测 |

脱敏汇总已留在 [分类烟测 JSON](pi-routing-classification-smoke-2026-11-01.json)，这只是历史报告副本，本轮未重跑真实调用。

这是一轮小样本烟测，没有重复采样或独立业务测试集；网关直接请求也不等于完整 Pi Agent 端到端运行。不能据此宣称普遍准确率提高、总成本下降或延迟改善。超时请求无法确认服务端用量，因此费用保持未知。

决策：保留现有分类模型与 medium 档位，不部署新服务，不启用每次回答的语义评审。先积累可脱敏、可验收的真实业务样本，再比较分类器及最终任务表现。Arch-Router 不在当前网关目录中，本次未下载或部署；语义路由和其他专用预测器尚无可比较的本地实例。

参考：[Plano 编码任务路由示例](https://github.com/katanemo/plano/blob/main/demos/llm_routing/claude_code_router/README.md)、[RouteLLM 与阈值校准](https://github.com/lm-sys/RouteLLM)、[Copilot Fusion 执行方式](https://docs.github.com/en/copilot/concepts/models/copilot-fusion)。采用任务偏好、轮内模型保持、可测量路由和有限升档；未整套引入框架。

## 验证与边界

规则、版本、编辑/取消/失败、试判、固定选择、继续任务、缓存、费用与修正均有可执行回归。Pi 原生持久化验收使用临时配置和 Mock 提供方，不发送真实请求、不打开桌面。Rust 验证规则参数传递、扩展文件打包和控制通道。

覆盖率只针对实际加载的路由、规则和评测模块；通过字符串转译执行的 TSX 另有行为测试，不以 Node 覆盖率声称其覆盖。未启动 YAM/Chrome 验证视觉布局，未构建或替换 YAM.app，未新增依赖，未提交、推送或发布。


## ChatGPT 订阅与 Magpie 通道分离（2026-11-01）

模型目录合并 Pi 原生可用模型与可选 Magpie `/v1/models`。ChatGPT 订阅由 Pi 自己的登录和 OAuth 管理，YAM 只通过 `ModelRegistry.isUsingOAuth(model)` 读取认证类型，不读取、复制或转发凭证，也不按 GPT 名称推断订阅。已有其他 Pi 原生连接仍保留。目录、选择值和历史始终使用完整 `provider/model`，同名模型不会合并。

Magpie 的普通文本模型使用 OpenAI-compatible `/v1/chat/completions`；已有 `yam-gateway/codex/*` 选择继续使用 Responses 协议，避免改变旧会话的模型身份。注册仍只使用网关自己的占位认证，不使用 Pi 的 ChatGPT Token。模型必须提供有效的上下文、输出限制及文本输入能力；无效条目不参与选择。非推理模型也可发现，固定关闭推理时可使用；自动档位仍遵守能力校验。

新建配置不再写死 Magpie 的 Codex 模型。检查目录后，明确选择轻量、强模型与分类角色；若希望全部消耗 ChatGPT 订阅，请为三个角色都选择标记为「ChatGPT 订阅」的原生模型。其他服务选择 Magpie 目录中的模型。分类默认跟随轻量角色，试判使用分类角色，自动回复修正使用强模型角色，因此它们也可能将上下文发送给相应提供方。已有会话和保存的默认参数不会自动迁移到同名原生模型，可明确修改后应用。

Magpie 目录故障作为独立警告展示，并从候选目录移除失效的网关模型。原生固定选择、原生分类/试判、输入和压缩不受全局网关开关阻断。自动路由只在最终需要失效的网关角色时停止；已保存的网关重试、原生 `/model`、输入与压缩入口也不能使用旧目录绕过故障。订阅分类响应失败（含 JSON 合法但字段无效）明确停止，不尝试付费模型；订阅轻量回复不自动跨到付费角色做质量修正，同为订阅的角色仍可升档。原生执行失败保持原有模型身份，重试仍需用户明确发起。刷新连接只刷新目录和校验选择，不重发任务。

状态区标注通道来源，并显示实际回复的输入/输出 Token。这不是账号剩余额度，也不是包含分类、失败请求和升档前回复的总账。OAuth 订阅不按 API 目录单价计算现金费用，不参与基于 API 价格的缓存保留优化；涉及订阅的现金总额保持未知。旧历史若没有当时认证来源和用量，保留原记录，不按当前登录状态补造计费事实。

本次验证使用 Mock 与临时 Pi SDK 配置；不打开登录浏览器或 YAM，不调用真实模型，不修改本机登录、全局模型配置或已有会话。Magpie 兼容端点只做了无模型参数的校验请求，未发送任务内容。
