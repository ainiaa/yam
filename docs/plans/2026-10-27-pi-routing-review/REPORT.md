# Pi 自动路由复核与 lint 修复验收

作者：Jeff.Liu

日期：2026-10-27

本轮复核与修复完成。应用已重新构建、安装并重启到 `/Applications/YAM.app`，仍为固定 `com.yam.desktop` 单实例。只修改了本轮基线清单中的 8 个文件，其他未提交内容予以保留。原交付记录保持不变，本报告是后续复核结果。

## 修复的遗漏

1. **网关故障时错用其他提供商**：原生恢复找不到物理模型时可能选择其他已认证模型。现在网关目录失败就切入拒绝推理状态，同时拦截输入与压缩，不再保留该回退模型发送请求。
2. **原生模型切换或启动时丢失锁定**：原生 `/model` 可能先 clamp 推理档位。现在根据原生分支记录验证原锁定档位，目标支持时保留，不支持时恢复原选择。显式启动档位被原生 clamp 时停止推理，等待用户纠正。
3. **内联档位被默认 off 覆盖**：指定物理模型时，不再注入自动模式的 off 默认值，保留 `provider/model:high` 等原生选择与物理模型的原生默认值。
4. **输出截断误报完成**：最终响应以 `length` 结束会报告 TurnFailed；中间错误后真正成功的重试仍按最终成功结果报告。
5. **其他边界**：图片兼容性检查覆盖 direct 压缩和 continuation/retry；网关参数解析遵守最后一个选项、字面量值及 `--` 提示词分隔符，防止把提示词误当网关配置。
6. **原生文件归属**：YAM 的一条历史记录绑定一个原生文件。Pi 终端内 `/new`、跨文件 `/resume`、`/fork` 会提示使用 YAM 新建/继续并保留当前文件，避免旧历史指向错误会话；YAM 新建/历史继续仍可用。原生同文件会话树导航不受该文件归属保护限制。

明确控制：若要降低锁定档位，先在 `/yam-route effort` 中选择新档位；单独切换模型不会默默降低已有锁定。

| Codex 私有文件替换 | 合并嵌套条件，保持相同字节不重写、私有文件和软链拒绝、原子替换 |
| Codex 路径重定位 | 合并相同分支，保留 cwd、规则/压缩文件路径以及原推理/模型字段 |
| Git 查询函数 | 用 QueryOutput 汇集差异与清单输出参数，保留共享查询、取消、忽略规则、过滤器及清理保护 |
| Node 测试 | 用 `slice::from_ref` 替代多余克隆，保持已安装 Node 优先且不下载的断言 |

没有添加 allow、关闭 lint 或删除验证。新增保持行为的测试在重构前先运行通过；严格 lint 先复现红灯，再验证绿灯。路由缺陷分别补充了失败测试。
