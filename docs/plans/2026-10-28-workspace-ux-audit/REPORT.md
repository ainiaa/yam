# 工作区、路由摘要与焦点后续审查

作者：Jeff.Liu

本轮已确认并闭环四处 UI 缺陷，没有修改官方 CLI、Pi 原生扩展、模型参数解析、认证、上下文或会话持久化代码。原生源码与本轮基线的比较已通过，见 evidence/native-source-unchanged.json。

| 问题 | 根因与修复 | 失败／成功证据 |
|---|---|---|
| 工作区隐藏后重开丢失选中的 Git 差异及比较侧 | 组件虽未卸载，active effect 仍清空内部状态并按列表重新加载。分离作用域重置和可见性处理，隐藏时取消读取，重开按原文件／staged 或 worktree 比较侧刷新 | 实际组件＋控制器用例覆盖两个比较侧；真实 React 浏览器闭环覆盖选暂存差异、关闭、重开和保留选择 |
| 已结束的 Pi 会话摘要可能一直不可用 | 首次文档隐藏导致跳过读取，或首次读取失败后，inactive 会话不再安排读取。现在首次成功读取前保持只读重试，成功后仍停止结束会话的常规轮询 | 初次 hidden／初次临时失败的两个确定性场景均由红转绿 |
| 模型目录请求失败没有提示 | 原 catch 忽略错误；现显示独立目录错误，并复用原有连接刷新恢复。无关的推理设置成功不会清掉目录错误，成功重新取得目录后才清除 | 目录失败、无关设置、刷新恢复用例；动作只有 catalogue/set/retry，不提交任务 |
| 重复打开当前文件不能返回编辑器焦点 | ready 只在初次装载变化，同文件再次打开尤其脏缓存不会重挂载；新增仅用于 UI 的焦点请求序号，并在编辑器完成 editable 同步后处理。继续检查原始焦点意图与面板可见性 | 浏览器先复现，再覆盖干净／未保存文件重复打开；同时保留延迟文件加载不抢终端或其他控件焦点的旧回归 |

只增加必要的 UI 请求标识和错误状态；复用原有 Git 控制器、连接重试、CodeMirror 聚焦和 Pi 控制接口，没有新增依赖或新的执行机制。
