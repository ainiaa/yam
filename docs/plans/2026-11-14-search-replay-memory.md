## 顺序

1. **基线**：隔离扫描中计数真实xterm getCell创建、快照/全帧次数和耗时；规范YAM上使用固定2000行、固定普通输出、本地无付费模型任务，打开同一搜索、持有同一视口，记录完整进程组footprint。性能窗口不并行跑测试或改源码。
2. **搜索快照**：先补回归，复用xterm的公开`getNullCell/getCell(x,target)`接口；局部对象不跨异步扫描共享，尤其验证下一行宽字探测不会污染当前格坐标。
3. **重放**：先测试普通文本在活动搜索与持有视口时的真实解析等价性、滚动截断、选区、查询切换与取消；只有证明安全才接入原增量路径。活动搜索仍基于最新缓冲，手工选区保护不变；未知控制、模式、decoder、身份、代次、尺寸、不完整数据继续回退全帧。可选hint的旧版兼容保守。
4. **集成**：定向红绿、前端覆盖率、原生覆盖率一次、普通构建/Clippy/doctest按影响面；规范debug打包、同场景实测、真实桌面验收、所有owned任务停止和通知策略复原；独立只读复核与正式计划审计。

## 冻结验收

- 搜索快照逐格临时cell创建降为每次扫描常数级，搜索文本、软换行、CJK/emoji/组合字、空行和结果定位相同；异常/取消/并行场景不污染。
- 同步普通文本在活动搜索和历史视口下无需逐块RIS重放；100次连续输出应复用当前buffer并保留实时结果、滚动视口和选区语义。所有既有不安全回退、所有者校验和有界FIFO保持。
- 内存按真实进程physical footprint汇总并逐进程记录；原始尝试不丢弃。跨运行核心进程身份可不同，单个窗口核心身份必须固定；需要正常重启时明示，不能算成优化收益。
- 保留2000行；不删除用户历史、不加入产品强制GC、不改变App名称/identifier、不启动其它桌面应用、不发布。数值阈值在基线完成、候选开始前冻结；未达标保留失败并继续定位，不改阈值求通过。

### 根因与最小修复

1. `terminal-find.ts`原先逐格调用不带target的`getCell`。实际安装的xterm6会为每格创建CellData；2000保留行、100列及可见行的一次完整扫描约20.24万个临时cell。改为每个同步/异步扫描各自创建一个scratch，传给公开`getCell(x,target)`；读取下一行宽字之前保存当前格的字符和宽度，避免可变scratch污染坐标。并行/取消扫描不共享对象。
2. 原投影把活动搜索和历史视口视作必须全帧的情形，普通每秒输出也会触发RIS及解析重建。前后端现在仅对已同步、正常模式、完整解码、控制代次/尺寸/身份相同、经普通Unicode及成对CRLF校验的输出追加；手工选区、不确定状态和未知VT控制仍回退权威全帧。FIFO继续限制为256块/256KiB。搜索自有高亮在接纳追加后清除，在同批解析结束后刷新一次。
3. 独立质量复核发现两处P2并已在本轮关闭：解析期间用户滚动可能被投影守卫忽略，连续输出也可能不断取消尚未完成的异步搜索。持有视口的追加批次用一个公开marker推导滚动截断应产生的位置，只有真实偏移才走原所有者滚动同步，批次结束必释放marker；搜索忙时走原100ms合并全帧路径，使当前查询可以完成。marker缺失、失效、抛错等继续保守回退。

未引入依赖、强制GC或后台压缩；保留2000行、VT语义、旧hint兼容、用户选区及原权限边界。
