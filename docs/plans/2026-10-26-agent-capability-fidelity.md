# YAM 第一批 Agent 能力保真修复计划

作者：Jeff.Liu

## 目标与边界

修复本轮确认的五个问题，继续使用官方 CLI 执行任务。只改变配置继承、环境覆盖、参数兼容和会话恢复，不实现新的 Agent 循环，不在本批新增 Pi/OMP 引擎。保留既有凭据隔离、项目权限、原生会话 ID 和历史记录。

当前工作区已有未提交改动；以本轮开始时的文件内容为基线，不覆盖其他工作。

## 顺序与验收

1. **Claude 配置继承**：先用合成目录复现全局能力资源缺失，再复用原生发现机制保留 settings、指令、Skills、Agents、Hooks、插件和 MCP 配置；不复制原账号登录凭据，不改原配置。
2. **环境保真**：先验证 effort、输出预算等被误删，再将过滤限制到认证、端点和确实冲突的宿主配置；PTY 与探测子进程行为一致。
3. **参数兼容**：先覆盖推理配置、profile、功能开关的拒绝路径，再允许正常原生参数；显式覆盖受管路由、认证或会话身份的冲突仍需拒绝或明确降级状态集成，不能静默改模型。
4. **会话恢复**：先复现带正常参数的 Codex 会话无法恢复，再复用原生 resume，保持原生 ID、工作目录、启动配置和上下文；拒绝混入其他会话或远端模式。
5. **旧 Codex 路径**：新启动统一走配置继承；旧会话保留原历史目录与 provider 身份，消除旧最小配置和无条件禁用搜索，兼容现有 UI/trust 元数据。升级失败不得损坏旧历史。

每步都先取得目标行为缺失的可执行红灯，再改生产代码，定向绿灯通过后报告结果并进入下一步。

## 最终验证与安装

- 执行受影响 Rust 模块、前端回归、构建与覆盖率；真实 CLI 检查只用无界面模式和合成配置，不读取真实凭据、不发起付费模型任务。
- 对五项验收和认证边界做独立复核，修复本范围 finding 后重新验证。
- 构建固定 `apps/desktop/src-tauri/target/debug/bundle/macos/YAM.app`，核对 `YAM` / `com.yam.desktop`。
- 按用户授权重新安装到现有安装位置并重启；执行前提醒保存草稿，优先正常退出，不强杀仍在工作的 Agent；核对只有一个 GUI 实例及运行的 bundle 路径。
- 未经额外授权不 commit、push、tag 或发布。模型真实效果没有实测时，不把配置保真验证写成模型基准成绩。

## 证据

结构化计划和逐步测试回执保存在本机临时目录 `/tmp/yam-agent-fidelity/`，包含源文件基线摘要和原始验证命令。完成后在本计划中补充实际结果。

## 实现结果

五项修复已落地，继续调用官方 CLI，没有新增依赖或 Agent 执行循环。

- Claude 继承能力配置和项目 MCP 开关，按会话保存原生设置；恢复保留会话内调整，新会话读取当前全局配置。登录凭据和原始历史不复制。
- 认证与路由使用明确的环境变量过滤，保留 effort、输出预算、模型别名和无关运行参数；PTY、探测和项目环境一致。
- Codex 推理参数、profile 和功能开关透传；受管连接、工作目录、会话身份冲突仍拒绝。Claude 内联 settings 保留最后一项的原生字段并追加状态 Hook。
- 恢复复用官方 resume，清除旧 prompt，保留原生 ID 与参数；Codex/Claude 没有可信回调 ID 时使用官方会话选择器。Claude print 模式不能混入交互恢复。
- 新 Codex 启动统一继承原生配置；旧路径保留原目录、数据库和 provider 身份，移除无条件搜索禁用并迁移能力配置。私有连接快照以 0600 权限保存子进程所需环境值，不写入命令行、历史或原账号配置。

官方 Codex 与 Claude CLI 的工具调用和会话连续性共四项本地模拟接口检查已通过；没有调用真实模型或使用真实凭据。前端回归 1,874 项通过。最终后端、覆盖率、构建与安装检查以本轮结束时的原始日志和结构化 T6 回执为准。

Claude 文件型 `--settings` 直接交给官方 CLI，保持文件目录对应的权限和 sandbox 路径；该情况不注入 YAM 状态回调，恢复仍可使用官方会话选择器。不会复制配置到其他目录或在项目中生成额外配置文件。

全量回归发现的旧夹具已同步更新：配置发现允许读取合成配置目录；晚期篡改测试从实际启动命令定位新的会话快照，继续验证篡改在进程启动前被拒绝。
