# Pi 自动路由交付计划

作者：Jeff.Liu

目标：在 YAM 同一 Pi 原生会话内按任务选择模型与推理档位；保留手动锁定、公开上下文、原生工具和重启恢复。官方 CLI 的启动、配置和认证链路保持独立。

## 范围与顺序

1. 冻结已有脏文件基线，先补策略、启动、恢复测试。
2. 用 Pi `registerVirtualModel` 实现模型与推理路由；继续/重试沿用实际模型，压缩交给原生实现。
3. 增加 Pi 启动入口，复用 YAM PTY、后台所有权、历史恢复、回合通知和评审意见输入。
4. 执行单元测试、真实模型测试、前后端回归、只读审查和构建检查。
5. 构建固定的 YAM.app，安装到现有位置，重启单实例应用并验收。

## 已决实现细节

- 复用 Pi 原生 TUI，而非再造聊天 UI 或 RPC 聊天宿主。原生 footer 同时展示选择与实际执行模型；`/yam-route` 管理自动与推理锁定，`/model` 选择具体模型即手动锁定。
- 虚拟模型 `yam/auto` 的原生 `off` 值表示自动推理；high/max 等表示精确锁定。此含义只适用于 YAM 虚拟模型，物理模型仍使用原生语义。
- 自动：独立只读任务 medium，编码 high，高风险 max；支持表中缺失时向上找兼容档位，不能满足则停止。分类失败保留 strong 和已有高档位。工具继续/重试不重新分类，不在工具之间降档。
- 模型角色是显式可编辑的 `--yam-small`、`--yam-strong`、`--yam-classifier`，值为 Pi 的 provider/model。分类通过 Pi 原生 registry 与认证发出，工作模型保留原生输出上限、工具和会话上下文。
- 本机默认预填 Magpie 的明确 Codex 路由；可删除 `--yam-gateway` 并使用 Pi 自己配置的模型和认证。目录元数据动态发现；不写全局 Pi、官方 CLI 或 Git 配置。
- YAM 以专用 UUID 文件名管理原生 JSONL 会话；内容和原生 session UUID 均由 Pi 创建，YAM 历史保存的是该稳定文件引用。恢复校验项目物理路径，使用原文件而不重建历史。
- 原生 model/thinking 选择在恢复时优先于启动默认值；路由状态存于原生分支 custom entry。网关物理模型必须在 Pi 解析恢复选择前注册。
- 初版能力基于已验证的 Pi 1.4.0；其他版本明确报错，不静默失去路由。Pi 单独安装，不捆绑/安装新依赖。

## 验收矩阵

| 行为 | 验证 |
|---|---|
| 任务分类、故障回退、档位映射、容量/图片保护 | Node 策略与扩展测试 |
| 原生 continuation/retry 稳定、手动锁定 | 扩展测试、真实网关测试 |
| 随机事实跨模型记忆、删除原文件后恢复 | 真实 Pi + 生产扩展，SIGKILL 后复用原 JSONL |
| Pi 启动、原参数透传、重启不覆盖原生选择 | Rust 测试 |
| 文件权限、路径别名、项目不匹配、软链与损坏拒绝 | Rust 恢复测试 |
| YAM 回合通知、历史继续、评审输入 | 桥接契约及前端测试、安装后实测 |
| 官方 CLI / 既有功能 | 全前端、Rust 单元回归及构建检查 |

## 明确边界

原生上下文压缩是摘要而不是逐字无损；不同模型的私有推理状态不可保证迁移。同名推理档位不代表不同厂商相同计算量。Pi 工具以本机用户权限运行，不等同于官方 CLI 的操作系统沙箱。官方 CLI 历史不自动转换为 Pi 会话。

执行结果见 [REPORT.md](REPORT.md)。plan.json 保留冻结时的初始状态；宿主计划面板已逐项完成。
