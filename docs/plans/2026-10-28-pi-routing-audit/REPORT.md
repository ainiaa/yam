# Pi 自动路由审查与修复

作者：Jeff.Liu

本轮范围为 Pi 扩展、路由状态栏、中文文案和测试。未修改官方 Codex/Claude CLI 启动、参数转发、配置继承、认证或恢复实现，未增加依赖。

## 已闭环的问题

| 问题 | 修复及依据 |
|---|---|
| 切换原生模型时，模型默认 high 可覆盖用户明确设置的 off | 将明确 off 纳入原有推理锁恢复逻辑；不兼容档位仍拒绝或恢复原选择 |
| 崩溃发生在原生推理记录落盘后、扩展偏好回调前，重启读取旧偏好 | 尊重较新的独立原生 thinking 记录；模型切换导致的 clamp 不冒充用户新选择 |
| 无 YAM 偏好记录的旧树分支继承其他分支的选择 | 使用 Pi 原生 buildSessionProjection 恢复模型与档位并记录偏好；不重建或改写工作消息。无法辨别自动意图的 off 保守保留为 off |
| 逐项立即应用导致模型／推理组合难以调整 | 两项独立选择后一起应用；可取消。状态已更新时拒绝旧草稿覆盖 |
| 控制期间旧轮询覆盖新状态 | 控制前后使旧读取失效，保留后端 revision 校验 |
| 分类模型不可用时，已有任务续跑／重试／压缩受牵连 | 续跑和重试沿用 Pi 原生 previous/failed 物理选择；直接压缩只验证实际使用的模型 |
| 保存 max 后，携带旧 --thinking high 重启误报不支持并阻塞任务 | 已恢复偏好不再接受这条启动阶段误报检查；真实 Pi 恢复已验证。新会话及无保存偏好的显式参数检查仍保留 |

以上修复均先观察失败测试，再修复并运行回归。边界包括 high/max/off、模型切换 clamp、旧分支、不兼容档位、并发旧读取、过期草稿、分类角色缺失及原生参数恢复。外部只读复核及两项发现的处理见 evidence/readonly-review.md 和 review-disposition.md；最后的启动参数误报由额外真实 Pi 实验复现并单独修复。

## 验证

- Pi 路由与 UI 专项：58/58 通过。
- 前端全量：1993 通过，3 项原有 opt-in 检查跳过，无失败。
- Rust 全量：1056 通过，25 项原有检查忽略；行覆盖率 87.18%，高于 85% 门槛。
- Clippy：all-targets、-D warnings 通过。
- 前端与 macOS debug app 构建通过；签名和应用包校验通过。
- 无界面浏览器连接真实 Pi 控制接口：配置表单、模型／推理同时应用、连接故障重试、1050px/430px 界面通过；16px 内边距且无横向溢出。此为实际 React 组件联调，不是 macOS WebView 点击测试。
- 安装实测：真实网关发现 8 个模型；固定模型+自动推理、自动模型+max、high/max/off、删除文件后从会话回忆、同一原生会话重启、故障恢复不重发任务、更新的原生推理记录在模拟崩溃后恢复均通过。
- 独立真实 Pi 1.4.0 进程：原启动参数 high、保存 max 后重启，恢复 max 且无错误；使用真正落盘的原生会话文件。

详细原始结果、失败／成功测试输出、源码摘要及安装校验位于 evidence/。本轮保留 Pi 原生上下文、工具调用和会话持久化，不用分类摘要替换工作上下文。分类结果仍可能判断不准，保守回退和用户固定档位继续生效。

## 交付与范围限制

应用标识 com.yam.desktop、版本 0.1.10；重新安装并重启 /Applications/YAM.app，旧包备份保留在 /tmp/yam-before-pi-routing-audit-closure-install.zip。仅维护约定的 YAM debug bundle。验收只使用自建临时项目和会话，归档后恢复原通知状态，不改用户全局 Git、Codex、Claude 或 Pi 配置。

本轮未做所有模型／提供商的质量等价评测，也未启用会启动无关桌面应用的 opt-in 测试。不能据此承诺所有模型在任意任务上质量相同。原生树分支边界由原生投影 API 的回归测试覆盖，未在真实桌面中逐项点击 /tree。

最终补充验收：最后安装版 high→max 修改后停止、继续原生会话并从已删除文件的会话上下文回忆成功。最终仅有 1 个 GUI 和 1 个后台进程；所有 4 份 Pi 源文件与安装二进制嵌入内容一致。最后 2 个验收会话已归档，活动会话 0，常规历史数量 156，通知暂停恢复为 false。
