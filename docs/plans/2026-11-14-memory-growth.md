# YAM 长测内存增长排查与修复计划

作者：Jeff.Liu

## 目标与保留行为

解释上一轮八小时观测中 WebContent、Node 解析器及后台的内存变化，区分有界终端历史、缓存/分配高水位、反复投影分配和无法回收的引用。只修复有复现证据的原因，不用减少 2,000 行历史、降低 16 会话并发、关闭检查或在产品强制 GC 获得通过。保留终端内容、Unicode/样式、光标、滚动、选择、输入权限、后台单实例及已有工作区改动。

起点 HEAD `b1a7b9d4d05c7af7d6929591dab13f4edabf9a0c`，源码指纹 `eb116a94067534fe27ba6f298be1bbfd43ced147ac90ab237e057c370b4b0943`，171 项既有脏文件。证据和起点副本放在 `.artifacts/memory-growth-20261114/`，不覆盖上轮长测原始记录。继续使用 Converge Plan/Converge 与 Ponytail，当前会话顺序执行；本机工具的实际证据不冒充历史受管 Single State/Trace 认证。

## 测量规则

- 旧样本只能描述趋势，不能把 8→16 会话的总量变化当固定负载泄漏，也不能把进程物理占用等同 JavaScript 活对象。
- 对照在相同内容、尺寸、历史上限及更新数量下运行；同时记录正常占用和释放/静默后的占用。观测者开销单列，不把后台自身采样器临时进程算泄漏。
- 沿用已获用户确认的最多 3 次/2 秒完整采样窗口；所有原始尝试留存，核心进程身份变化或窗口耗尽即失败。
- 定位前不凭“平台缓存”解释；修复后不能只看总量最低点或一次 GC。稳定阶段至少分为三个窗口，报告中位数与线性趋势，阈值以相同负载改前重复波动和可解释的对象上界共同确定，并在改后运行前冻结。
- 默认测试无 GUI，不新增依赖、应用身份或并行验收包。真实验收沿用用户已授权的本机 YAM，必要重启仅限无活动用户任务时；不停止用户任务，不改通知全局设置，不调用付费模型。
- 不安装、签名、公证、提交、推送或发布；不声称短对照等于第二次完整八小时。

## 实际结果

本轮已确认并修复三类分配压力：内存采样触发整个 App 重绘；小片普通输出触发 2,000 行全历史重放；未打开的会话仍向 WebKit 发送并缓存全部原始输出。复用既有生命周期/claim、解析器身份/控制代次及字节偏移，普通分片和同批输出使用有上界的 xterm FIFO，复杂 ANSI/TUI/未知状态仍走原权威帧。没有减少历史或并发，没有在产品强制 GC，没有更改应用身份或安装发布。隔离实验未发现保留的旧 Buffer 无法回收；这不排除未知泄漏，也不把物理占用等同活对象。

### M1 结论与 M2 收窄（实现前冻结）

- 固定 16 会话基线完成 2,160 秒、205 份完整样本，关键进程身份固定；所有本轮任务已停止。解析器隔离实验中，16 × 2,040 行、100 列的行数组固定 39,168,000 字节，解码缓冲 8,388,608 字节，滚动期间 GC 活堆约 19 MiB 稳定；销毁后 ArrayBuffer 约 0.08 MiB，RSS 仍约 247 MiB。隔离 GC 不代表产品运行时行为。
- 实际前端稳定阶段三个窗口中位数 262.9 / 217.7 / 246.3 MiB；静默尾部 268.1→339.5 MiB，后续同 PID 又自然降至约 220 MiB。未见 DOM/AX 累计；主要 malloc 增量为未分类 non-object，不能直接归给 React。同步 2,400 次、真实异步 120 次投影后，旧 Buffer 弱引用均可回收，正控制保留的 30 个可正确检出。原异步 500 次试验超时保留为失败，不改写为通过。
- 完整 12 分钟 A→B→A→C 观察者实验通过，70 样本、2 秒稳定窗口原始尝试保留，16 任务清场。完整日志每轮约 20.5 MB，帧约 1.5 MB；帧路径后台中位数约少 3 MiB，但 Node 中位数约多 4.5 MiB，未证明全进程净内存收益。保留原采样方式作为本轮同负载控制，避免把成本转移当优化。
- 独立只读复核确认每 5 秒内存采样写入 App 根状态，会重新执行历史排序、项目分组及 JSX/回调创建。M2 仅将状态、effect 和原 span 迁至 App.tsx 顶层稳定的 MemoryUsage 组件，保留 invoke 包装、翻译、刷新频率、可见性、错误/过期/卸载处理。测试修改限定 memory.test.mjs、workspace-simplicity.test.mjs；不增加依赖、不改解析器/终端保留策略。不声称已修复永久引用泄漏。
- M3 继续使用相同 live-fixed 合成负载和完整日志观察者，候选之前冻结物理占用对照门槛；新驱动仅补墙钟、采样间隔与清场记录，不改变负载。前端正常采样的状态更新不得进入 App；整体验收仍须实际运行至少 30 分钟稳定及 5 分钟静默。

证据目录 `.artifacts/memory-growth-20261114/`：`m1-attribution-complete.*`、`review-scope-checkpoint.*`、`native-baseline-1/`、`native-observer-aba/`。提前于 ABA 结束执行的一次聚合核对因 result.json 尚不存在而失败，原回执保留；待真实结束后核对通过，不代表重新运行长测。

### M3 首候选失败及有限修复续轮（实现前冻结）

首候选 `native-candidate-1/` 在 183.6 秒内 WebContent 超过预冻结峰值 385.59 MiB，观察到约 450 MiB；提前结束仅本轮登记的 16 任务，result=fail、supervisor exit=1、全部任务 stopped，源码未变，通知策略已还原。本次不算完成 30+5 分钟，也不修改旧门槛。候选实际启动了新后台（40937/40940），原对照契约中“保留暖后台”的假设与实际不符；后续报告以实际 manifest 的进程身份和启动时间为准，不据此宣称组件迁移造成某个百分比变化。

新增证据表明每行约几十字节的输出会触发约 88 KB 的 2,000 行全帧重新序列化、RIS 重置和重放。隔离实验证明对象可回收，不代表这种反复分配开销可接受。先验证安全边界，再增加保守增量路径：仅正常屏、解析 token 完整、默认字符集和完整滚动区域、非插入/原点模式且行首的服务端帧提供可追加提示；仅已同步、连续 offset、可见实时底部、无查找/选区/移动/恢复/解析中的视图接受不含控制序列且 CRLF 完结的普通文本增量。Unicode、样式和历史上限保持；其他情形、缺提示、乱序/缺口、模式/视口/尺寸/生命周期变化都保留原权威全帧路径。沿用已装 xterm 6.0.0 和现有 consumeOutput，不引入依赖或新原生命令，不绕过权限。受影响字段和重放等价性先红灯后实现；不够安全则不启用该路径。

独立复核还确认移除根采样后会暴露旧选区结束回调未刷新按钮的依赖：先为实际 pointerup 回调补回归，再仅在当前有效选区结束时通知现有 recovery revision。纳入同范围复核，不以旧周期刷新掩盖状态缺口。

新增写入仅 `terminal-frame.ts` 的可选帧提示类型、`terminal-service.cjs` 的保守提示、App 的受控增量消费和选区事件，以及 `terminal-memory.test.mjs` / 已有 service 与 memory 回归。Rust、日志采样方式、并发/历史、依赖与发布范围不变。新候选继续原门槛和完整 30+5 分钟对照。

### 增量路径安全审查补充（尚未启用，Rust 写入前冻结）

第一次原生只读方案复核在 600 秒超时，未取得批准；保留实际失败记录。随后有限的无工具源码评估指出仅布尔提示不足以处理跨窗口无输出控制变化、旧实例事件及渲染端状态。当前新 helper 仍未接入事件路由，相关路由回归保持红灯，不能把原型当已启用优化。

继续沿现有消息链补齐必要约束：服务端终端条目维护饱和控制代次，resize / viewport / clear / prompt navigation / history restore 成功变更推进它；快照与 write 完成回执带相同解析器 instance 和 control revision，原生输出事件只转发严格验证且与会话匹配的写入回执，缺失/异常回执仅关闭增量能力，不损坏原全帧路径。前端要求帧与事件身份/代次严格一致；其他窗口改变控制状态后，下次输出必然回退。帧的 offset 与解析完成点须沿既有 log lock 核实；不得拼接未完成解析和已收日志偏移。

渲染端也检查已装 xterm 的解析器、字符串解码、字符集和滚动区域契约，增加组合字符、ZWJ、宽字符跨列及字节/控制边界等价性测试；任何无法证明的内部状态不启用。查找控制器或提示符导航存在时保守使用原路径，避免遗留 marker/decoration 引用。所有已写入但无法提交偏移的场景都要保持 dirty 恢复，异步尾部不得清除别人的 parsing/projecting。该补充只扩充现有帧/写入回执/输出事件的可选元数据，不引入原生命令、依赖、架构或用户设置；旧后台/旧事件自动走原路径。

Rust 改动范围按图谱进一步限定到输出回执、事件结构及其验证回归；由于此次需要原生源码修改，将按项目标准执行原生覆盖率全量一次、Clippy/doctest/调试打包，并重新独立复核。旧“Rust 未修改不复跑”的结论仅适用于叶子候选阶段，不能沿用为最终原生放行。


安全补充：控制代次可拒绝新状态下的字节，但无后续输出时仍须可靠通知。统一在现有后台控制分发的 resize / viewport / clear / prompt navigation 执行后，通过既有有界 relay 发出仅含 session_id 的 terminal-frame-invalidated 事件；成功和部分失败都保留结果并通知，权限/参数预检不扩大。前端仅锁存 dirty 并关闭增量，沿用完整帧恢复。已审计 App 仅两个 dirty=false 位置：轮询已经在读前清除；初次附着也改成读前清除，避免等待期间的通知被旧返回覆盖。增量回调必须拒绝 dirty 已重新置位的状态。这样不用额外的轮询周期、请求计数或用户设置，老字节和控制完成通知仍按既有队列恢复，无输出控制也不会无限停留旧画面。新增范围仅 background_dispatch.rs 的统一通知 helper、四个既有调用点及无 GUI 回归；background_owner 的原事件转发清单不变，新通知直接使用既有 relay。


本地回退模式不经过后台 relay 控制通知，因此原生输出仅在已配置的 background_owner 中附带可优化的 parser 身份；其他/旧模式保留无元数据事件，自动走完整帧。这把可选 parser 回执作为当前有通知能力的生产者契约，不新增原生命令。输入写权限不等于渲染资格；只读视图若已同步且实际 cols/rows 与最后帧一致也可显示增量，输入和 resize 权限仍完全沿用原路径。尺寸不匹配继续回退，不能靠 writable 标志掩盖几何差异。


最终源码复核确认两组夹具未同步新依赖，前端全量真实失败 11 项；仅补 links 的当前 sessionId 和旧协议 layout 的实际增量回退绑定，不删除断言或跳过测试。另对移除根定时刷新后的异步按钮状态补直接回归：仅当一次已提交的 App 渲染观察到所选 view 的 busy 时，在该异步忙碌结束后请求一次既有 recovery revision；普通输出未触发根渲染则不增加根刷新。用现有 useLayoutEffect 记录提交状态并补已结束竞态，覆盖解析、帧轮询和尺寸队列结束，避免每行都重新渲染工作区。新增范围仍是 App、既有 memory/terminal-memory 测试与上面两个夹具，Rust 内容不变；已完成的当前原生全量不重复执行。


### 第二候选未达标：普通文本分片缺口（新增修复前冻结）
