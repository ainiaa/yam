# YAM 易用性与稳定性优化计划

作者：Jeff.Liu

## 目标与边界

依据本轮调研，按可独立验收的用户结果顺序实施。基线 HEAD 为 `b1a7b9d4d05c7af7d6929591dab13f4edabf9a0c`，开始前全部未提交修改作为既有基线保留。机器计划、源码快照和实际命令记录保存在本机忽略目录 `.artifacts/usability-reliability-20261113/`。

保留后台任务、单实例、原生 CLI、输入所有权、保存失败保护、凭据隔离、历史数据和既有 IPC 契约。复用现有组件、历史查询和测试工具，不增加依赖。本轮不提交、推送、发布、安装或启动桌面应用；实际 GUI、中文输入法、通知横幅及真实厂商请求单列为未验项。

## 顺序与验收

| 步骤 | 独立结果 | 验收与定向验证 |
|---|---|---|
| T1 设置草稿保护 | 未保存设置不会因 Esc 或关闭而静默丢失 | 修改后退出可继续编辑或显式放弃；未修改直接退出；中文组合态不退出；跨页沿用现有确认；保存失败保留草稿。先补真实组件入口回归，再统一退出路径。 |
| T2 全历史搜索 | 命令面板能找到未加载的普通历史与归档会话 | 复用分页查询，明确作用域；支持加载更多、失败重试、取消和过期响应拒绝；结果选择只打开记录，不恢复执行；补齐路由、更新和模板入口。 |
| T3 启动与连接说明 | 用户能区分已配置、CLI 运行及可信回执状态 | 复用已记录事实，不将配置模型当成实际生效值；连接等待、失败、集成降级有清晰说明；旧回执不能冒充当前连接。 |
| T4 恢复链路验证 | 关键恢复与输入边界有连续、可执行回归 | 覆盖断连重连、旧响应、输入归属、历史只读与显式继续、通知定位及保存重试；复用 App 入口和已有隔离夹具，不启动本机 GUI。 |
| T5 性能基线 | 多会话切换和输出路径有可重复观测 | 复用现有无界面夹具，记录 1/8/16 会话的实际命令、样本、时长和指标范围；补齐可测的 UI 阶段观测；不把无界面耗时称为按键到像素或真实 GUI 性能。 |
| T6 集成复核 | 五项组合后无已知同范围回归 | 前端定向和完整覆盖率、TypeScript/Vite 构建、相关脚本检查；若修改 Rust 则按项目路线执行对应检查与一次全量覆盖率。独立只读复核最终增量，修复确认问题后复验。同步当前能力说明，保留历史证据。 |

每步先写或更新测试并观察目标红灯，再做最小实现，完成后记录命令、退出码、耗时和跳过项。每步开始及结束更新原生计划面板和可见进度。没有实际通过的验收不标为完成。

## 依赖与范围

同一工作区顺序执行，T1 → T2 → T3 → T4 → T5 → T6。共享入口为 `App.tsx`、设置导航、命令面板及中英文资源；不并行改写共享文件。先查 CodeGraph 调用面，再读具体源码。已有启动摘要、侧栏状态和职责拆分不重复实现。

性能优化以新基线为依据；没有热点证据时交付观测能力和基线，不引入新缓存、渲染引擎或架构。Apple 公证需要账户凭据与分发授权，不纳入本轮实施。
