## 结论

本机当前安装版的 New session 与普通 Delete 已取得实际界面证据。Fn+Delete 发现一个真实缺口：启动环境为 `TERM=dumb` 时，系统 zsh 没有相应删除键绑定。已修复源码并通过原生测试，但本轮没有构建替换或重启 App，不能将源码测试结果写成已安装版通过。

外部终端的自动化只通过了 YAM 内的选择与说明检查。后续通过用户操作 iTerm2、YAM 输出及进程证据，补齐了 iTerm2 输入、Ctrl+] 分离和回到 YAM 继续同一任务的验收。系统终端实际接入、关外部窗口及通知链路仍未验证。两种外部应用的自动化访问限制均未绕过。

后续还确认了外部视图的空闲重复重绘问题，并修复源码；当前安装版尚未更新，详情见末尾“后续协作验收与闪烁修复”。

## 删除键补充修复

1. 当前安装版的测试 shell 报告 `TERM=dumb`；系统 `/etc/zshrc` 根据 terminfo 绑定向前删除键。
2. 仅在自有测试会话改为 `TERM=xterm-256color`，并加载系统 zsh 配置、隔离用户启动文件后，实际界面输出 `FORWARD_SYSTEM=<abc>`。单独使用 `zsh -f` 会跳过系统绑定，不能作为修复成功证据。
3. 共用启动环境 helper 现在将缺失、空或 `dumb` 的启动器 TERM 补为 `xterm-256color`。其他有效 TERM 保留；显式会话配置仍在此后应用，可以覆盖该默认值。Windows 分支未改。
4. 修改仅涉及 `lib.rs` 的共用 helper，以及 `terminal_environment_tests.rs`、`coverage_state_tests.rs` 的既有测试。没有添加依赖或改写共享 CLI 配置。

## 后续人工验收

System Terminal 和 iTerm2 各执行一次以下步骤；只操作新建的专用测试会话：

1. New session → 独立测试目录 → Terminal → 本轮外部终端 → Start session。
2. 确认真实窗口出现，输入 `pwd` 和 `printf 'TASK_PID=%s\n' "$$"`；回 YAM 核对同一目录、输出、PID。
3. 输入 `printf 'DELETE=<%s>\n' abcX`，先按普通 Delete 再回车，应输出 `DELETE=<abc>`。测试 Fn+Delete 时输入 `abXc`，左移两次后删除，应保留 `abc`。同步记录 `printf 'TERM=%s\n' "$TERM"`；当前安装版的 dumb 失败不能写成通过。
4. 在外部窗口按 Ctrl+]；回 YAM 核对会话仍运行、PID 一致。另建同类型测试会话，只关闭它的外部窗口，再核对相同条件。

6. 仅结束这些新测试会话。更完整的权限、失败分支和静态网关命令见 [人工验收清单](new-session-external-terminal-manual-acceptance.md)。
