## 当前结论

通道分离、任务事实分类、可编辑规则、固定选择、任务连续性、有限回复修正和离线评测已有源码及回归。分类准确率、最终任务成功率、订阅额度消耗和跨提供方实际兼容性尚无充分业务证据，不能据合成样本宣布成本或质量已经优化。

本轮复核确认并修复一个费用记录缺陷：取消回复修正后，原回复被包装成 aborted 消息，新对象绕过对象去重，导致执行费重复累计。本次沿用成功修正已有的去重方式，标记包装对象；有明确修正费用时仍保留，未知费用不伪装为零。回归覆盖收到修正结果后取消、请求直接失败，以及包装消息再次回调。

## 后续顺序和退出条件

这些是建议阶段，不是自动执行授权，不新增后台采集、外部调用或依赖。

1. **真实集成验收进度**：当前源码的无界面 SDK 通道验收已执行，详见上方报告；Magpie 自动分类严格探针保留失败，不能称本阶段全项完成；GUI/安装包组合仍未覆盖。原计划要求：用已有登录验证原生订阅和一条非 Codex Magpie 文本路由；异常用隔离传输验证认证失败、额度失败、超时和不跨付费通道。覆盖新建、旧历史恢复、原生 `/model`、固定档位、输入保留和压缩。区分 10 月旧包验收与当前源码。启动 YAM/登录浏览器等桌面操作须另获明确同意，并复用固定单实例 YAM.app。退出条件是每个场景有实际来源、模型身份和请求次数证据，刷新不得重发任务。
2. **建立业务基准**：建议先整理 50–100 条经过脱敏、可验收的实际任务，包含短追问、长上下文、图片、代码、只读但困难、工具调用与失败恢复。手工确认标签，把校准集与盲测集分开；同题重复采样。记录最终任务通过率、误降档、额外升档、分类与端到端耗时及 P50/P95；记录模型/规则/提示词版本。API 费用和订阅 Token 分列，服务端未知用量保持未知。先由实际结果确定能接受的误差/延迟，再设发布阈值。
3. **一次只换一个变量**：先比较现有分类模型与一个更小候选；再按数据决定比较 RouteLLM 或 Arch-Router。保留原配置作为对照与回退点，不同时改变模型、提示词、规则和执行模式。未见稳定收益就保留当前方案，不追加服务或复杂配置。
4. **最后试更复杂执行模式**：若流畅但错误的回复构成主要失败，再试仅限无工具独立任务的单次语义 judge。只有相对基线有任务质量净收益、调用量/延迟在预算内且不跨越付费授权边界，才启用。Critique、多模型并行和在线自动学习继续暂缓。

当前优先级是集成真实性、业务样本与可比较指标。全量 Rust 覆盖率、真实额度耗尽、全部账户/模型兼容及桌面视觉组合尚未由本轮验证；不把定向测试、模型只读复核或过往安装报告当作这些验收。
