## Outcome and boundary

On macOS, a user explicitly previews and confirms cleanup of one YAM-created, fully checked-out, clean, inactive linked worktree. The owner revalidates it, removes only its Git registration using ordinary git worktree remove without --force, transfers the whole owned directory to system Trash using existing Foundation bindings, and durably records the actual outcome. UI says “Moved to Trash; branch retained.” It does not claim freed disk space, permanent erasure, or that restoring trashed files automatically restores Git registration.

No cleanup runs on pane close, terminal close, app mount, owner reconnect, record listing, failed creation or test discovery. Initial supported subset is Created + checkout_complete records with persisted physical identity. Incomplete/failed creation retains its recoverable record and directory for manual review; this slice does not recursively clean arbitrary residue. Branch commits made after a claimed session are allowed if the current checkout is clean and identity/branch relation still matches. Keep branch and commits unchanged.

Other OSs return fixed worktree_cleanup_unsupported before any cleanup filesystem/Git mutation. Creation/list/start remain as before. This is explicitly a macOS cleanup feature, not a three-platform deletion claim.

Safety model: close own-App ordinary/managed/resume start races with the existing owner lifecycle gate; refuse known dirty/untracked/ignored/nested/unsupported-filter source configurations and changes observed at preflight/recheck boundaries; preserve data on ambiguous results. Same-UID deliberate replacement of all app-private state is not an added universal attacker guarantee. Missing-path Git removal is a conditional way to avoid target status traversal when the registered path stays absent, NOT a common-config sandbox. Document this limitation in engineering evidence, not confusing implementation details in the user flow.

Ordinary late writes are not handled by permanently unlinking data. If detected before final disposition, stop and retain Q with recovery-needed; if an already-open handle writes during/after a successful Trash namespace move, its data remains in the moved tree. No recursive erase fallback, no clearing system Trash. This preserves bytes without promising to freeze external editors/builds.

## Concrete production flow

1. Preview is non-destructive. Obtain lifecycle gate, load bounded private manifest, resolve opaque attempt to exact record, verify Created/complete physical repo/common/target identity, canonical relation to one non-main/non-locked registered worktree and branch, no nested repository/gitlink, and current full cleanliness. Snapshot live/starting owner sessions and their lexical/canonical associations; reject target/descendant/alias use. Return a short-lived one-use opaque preview token plus exact source directory, branch, current commit and action=trash. Token binds owner operation context, attempt, manifest revision, physical identities and checked content/config inventory. No user path or branch from confirm is accepted.
2. Confirm uses only {attempt,preview}; absent/expired/mismatched/consumed token is refused. Acquire existing LIFECYCLE before manager session snapshot and retain it until this operation returns. Release session/history mutexes before Git/native work. Repeat all preview checks; changes invalidate confirmation. This blocks YAM starts during cleanup while keeping unrelated owner event processing free of sessions/history locks. Do not terminate active tasks for the user.
3. Private journal: add a small optional per-attempt cleanup map to the existing manifest, with a bounded operation token, original target, chosen Q path, parent+target physical identities, phase, fixed recovery reason and optional resulting Trash path bytes. Reuse existing exclusive-temp/file-sync/rename/parent-sync persistence. Keep old version-1 manifests loadable via a default empty map; validate map keys match known attempts, absolute bounded paths and phase/field consistency. Do not persist arbitrary NSError/stderr/commands/secret values. Public record projection may expose a small optional cleanup summary; update the strict frontend validator deliberately, not by accepting arbitrary keys.
4. Choose a collision-safe same-volume quarantine under a freshly exclusively-created, owner-private operation directory in the canonical original parent (or another proven same-volume private location). Validate parent/device and target identity; use platform no-replace semantics or a proven exclusive destination protocol. Do not overwrite an existing directory, cross-device copy/delete, or broaden permission changes to the user's original parent. Persist Prepared before moving; rename the whole target; verify held/source identity now at Q, original absent, and sync relevant parent metadata. Publish Quarantined. The opaque Q parent prevents accidental path collisions; it is not a writer-revocation primitive.
5. Recheck the source inventory at Q using the isolated read path with the captured Git metadata context, plus current source config/index/attributes/HEAD/relation. This cannot use git -C Q naively: the registry still points to original T. A changed result is recovery-needed with Q intact (or verified no-replace rollback only while original empty and registry intact); never proceed by ignoring a dirty result. Check original T still absent immediately before the Git call; if occupied, preserve both Q and foreign T and stop. Do not invoke Git remove on a known occupied original path.
6. Run one ordinary git worktree remove ORIGINAL with literal argv, existing installed Git/bounds, no --force, prune, reset, clean, branch delete or hand-written admin metadata deletion. Config/filter preflight remains mandatory; do not market absence as config isolation. On success OR nonzero/timeout, inspect the exact registration and source/Q identity before deciding next phase. Return code alone never means untouched, removed, or safe rollback.
7. Once registry absence is verified and Q bound identity remains, durably publish Unregistered. Q now contains data with an obsolete .git link; preserve it. Immediately before Trash verify Q identity and observed inventory again. A newly observed dirty/extra entry yields recovery-needed and no native call, even though registration is already gone. No automatic Git repair or recreated registration is required/claimed.
8. Persist Trashing BEFORE entering the native call. On existing owner request worker (or narrowly bounded existing blocking worker), call NSFileManager.defaultManager().trashItemAtURL_resultingItemURL_error on the exact Q, requesting returned URL. Do not introduce a general job framework. Keep operation single-flight via durable phase and lifecycle; a client timeout/disconnect is not cancellation of Foundation. Never spawn a second Trash call while the first can still be running.
9. Native success requires returned absolute file URL, lossless path extraction, original Q absent, and resulting item of expected identity/type. Use returned location, never predicted basename. Persist Trashed with actual path bytes and fixed status, update public state Removed only after this record is durable. Failure, missing result URL, identity mismatch, unexpected source presence or save error remains recovery-needed/unknown and cannot return Completed. If system Trash returns cross-volume or identity semantics that cannot prove this supported contract, fail closed/preserve truthful phase; do not silently broaden it.
10. Repeated confirm after a lost response returns the durable verified final result for that same operation, or recovery-needed/current phase; it never creates a new operation, retrashes a foreign path, or treats token reuse as fresh authorization. Remove only an empty app-created Q wrapper with verified identity if safe; if that trivial wrapper cannot be cleaned, retain a harmless recorded residue and report accurately without touching Q/Trash data.

## Clean certificate (must be production code, not booleans supplied by UI)

Reuse git_context's private shadow with safe built-in conversion allowlist and original-vs-shadow effective attribute agreement; copy/recheck required index, attributes and ignore sources within limits. Source config enumeration rejects nonempty filter.*.clean/.smudge/.process, unsupported attributes/excludes/conversions, unsafe Git environment and partial clone/object-format cases already unsupported. Never invoke a source status/diff conversion as the way to discover a filter. No filter overrides that change clean semantics.

The cleanup-specific result rejects tracked unstaged/staged changes, unmerged entries, all untracked including ordinary and ignored entries, submodules/gitlinks in both HEAD/index (including staged deletions), nested repositories and unsupported/missing/inaccessible paths. GitContext.dirty=false alone is insufficient: current normal query ignores ignored files and submodules. Bound time/output/file count and fail unavailable on overflow; never truncate to clean. Keep exact scope of ignored-file enumeration/known entries explicit; assert ignored-only refusal before rename.

Recheck effective config/attributes/index/HEAD and physical identity at commit and around quarantine. These rechecks establish observed freshness; they do not lock arbitrary user config or make Git's real common dir a sandbox. A writer must not cite tests that only mutate configuration before the first check as proof of unconditional race isolation.

## Finite durable phases and restart behavior

Use five operation phases: Prepared, Quarantined, Unregistered, Trashing, Trashed; recovery-needed is a fixed reason on a nonfinal phase, not a second workflow engine. Before/after each irreversible boundary, write the minimal state needed to interpret both possible outcomes. Existing RecordState::Removing can cover the nonfinal phases; Removed is only the durable Trashed projection.

Reconciliation runs when listing/previewing existing records. It classifies actual filesystem/registry evidence and may update the journal. It performs no new destructive work on app launch/list. A retry/rollback requiring a new mutation must be explicitly previewed/confirmed against the now-current state.

| Durable phase and observations after restart | Required reconciliation |
|---|---|
| Prepared, original bound T exists, Q absent, registry intact | no move observed; restore Created only after full identity/relation verification; previous token invalid; new preview needed |
| Prepared or Quarantined, Q bound identity exists, original absent, registry intact | recover as Quarantined, preserve bytes; offer explicit verified rollback/retry after checks, never call Trash automatically |
| original occupied by a different object, Q bound identity exists | conflict/recovery-needed; neither object touched; original basename is not ownership |
| registration absent, Q bound identity exists (regardless earlier phase) | recover Unregistered; no rename-back/repair claim; explicit new continuation preview may authorize Trash after current checks |
| Trashing, Q bound identity still exists | outcome not assumed; after owner restart no native worker exists, inspect source and any stored result; require new confirmed retry if unambiguous Q still exists |
| Trashing, Q absent, no recorded returned destination | unknown/recovery-needed, never Completed and never reissue remove/Trash on guessed path; preserve a durable user-visible record identifying operation/original source; no broad automatic Trash scan in this first slice |
| returned Trash destination was saved, Q absent, destination expected identity present, registry absent | verify and finalize Trashed after a crash before final public record publication |
| Trashed durable success, user later restores/empties Trash | retain truthful historical completion; do not delete/repair anything or reinterpret restored path as a retry target |
| missing/mismatched identities, invalid config/journal, unknown registry, timeout | fixed recovery-needed, preserve and block mutation; do not set Removed |

The crash window between actual Trash move and saving its returned URL cannot be made transactional by Foundation. This slice deliberately reports durable unknown/recovery-needed instead of promising automatic restoration or discovering an exact URL without evidence. That is a tested recovery behavior (no false success/no repeated wrong-target action), not an unimplemented generic TODO. If product acceptance demands automatic discovery of every such moved item, that is a separate bounded requirement to design before implementation, not silently included here.

Source directory .git becomes obsolete after registry removal. Recovery UI must distinguish “files preserved at quarantine/Trash” from “registered worktree restored.” Do not offer one-click worktree restoration without implementing it.

## Actual test-first matrix

All automated tests use owned temporary repositories and injected native Trash seam; no test suite default calls the real Trash API, user worktrees or agents. Put RED tests before production edits. Existing GitFixture, owner endpoint tests, lifecycle tests and actual component AST callback fixtures are reusable.

A. Happy-path owner RPC: create a genuine managed fixture, preview then confirm exact token, capture literal Git argv (ordinary remove only), fake native seam moves whole Q to a different collision-renamed owned destination, final registration absent, branch/commit unchanged, real files and late-handle bytes present at destination, durable Trashed/Removed; retry same request returns same outcome with exactly one native call.
B. Authorization: forged/wrong-owner/wrong-attempt/expired/replayed preview, changed manifest revision, target/common/parent identity replacement, locked/main/foreign worktree => before mutation refusal. Confirm never accepts replacement target path. Two preview requests and stale UI response cannot swap operation targets.
C. Clean rejection: real tracked dirty, staged, ignored-only .gitignore/info-exclude, untracked, nested .git, gitlink in HEAD/index including staged-delete, filter clean/smudge/process sentinel, unsupported conversion/config/attributes, missing paths/time/output limits. Assert no rename/Git-remove/native call, files unchanged and sentinel absent. Repeat changed config/index/attributes after preview but before commit.
D. Active gate: production owner wrapper with real manager session status/summary associations refuses live/starting ordinary/managed/resume child paths and aliases. Pending create holds lifecycle -> cleanup busy; cleanup holding lifecycle -> start busy/no allocation. Ended retained session alone does not falsely block if no process is active. Tests assert actual RPC entry, not only cfg(test) validate_cleanup booleans.
E. After-rename changes: hook writes new tracked/ignored bytes into Q before recheck => recovery-needed with bytes retained, no Trash. Hook recreates old path before final absence check => conflict, foreign sentinel untouched, no Git remove. Explicitly record that these deterministic checkpoints do not prove arbitrary hostile mid-syscall immunity.
F. Existing-handle late write: keep file handle through rename, fake Trash move, write after final pre-native snapshot; destination contains new bytes. No production erase function is called. This validates practical reversible disposition instead of a fake write-freeze claim.
G. Each boundary fault: before/after Prepared save, rename, Quarantined save, Git success/nonzero/timeout, Unregistered save, Trashing save, native move, returned-URL save, final public state. Reopen real manifest/list reconciliation; assert table above, no mutation during listing, no false Completed, and data/branch preserved. Include Git nonzero but registry absent and response lost after success.
H. Native seam: success path differs due to name collision; failure preserves Q; missing URL/relative URL/wrong identity/source still present => unknown not Removed; UTF-8 Unicode/spaces and byte-path conversion reject embedded NUL without lossy conversion. Real native conversion code is cfg(macos), existing binding must compile. No fabricated cancellation/timeout success.
I. Frontend real WorktreeControls callbacks/rendered controls: preview displays directory, branch and move-to-Trash semantics; no cleanup before explicit confirmation; cancel/root/owner/unmount defeats late success/error/finally; busy prevents double submit; response validates exact attempt/token/result; success refreshes matching record, does not call onCreated/onStart; recovery-needed is visible and no Start/Remove replay is enabled for Removing; unsupported platform message explicit. Stale parent selected Created value cannot keep a functional Start button for a record now Removing/Removed—child reconciliation or a narrowly approved App invalidation must be tested.
J. Regression: all T13 create/claim/start/owner/config tests, T12 isolated query tests and desktop tests remain green; TypeScript and macOS Rust compilation. Cargo deps/lock and creation behaviors unchanged. Native system Trash acceptance is a separate explicit synthetic-owned fixture stage and cannot be claimed from a seam test.

## Acceptance and freeze notes

Feature code PASS requires production endpoint + visible preview/confirmation/result + production guards + real journal reopen tests. A pure validator, disabled button, rename-only path or fake-native success is not native platform acceptance. Report source integration and actual native acceptance separately. Remaining unknown crash outcomes are accurately surfaced recovery states, not successful cleanup.

Before writer dispatch Root freezes: supported initial record states above; exact max limits/token lifetime from existing patterns; owned file set; summary DTO fields; native seam; explicit recovery-only continuation authorization. No unnecessary dependency approval, broad framework, auto-cleanup scheduler, permanent erase, branch removal, recursive trash discovery or Git registry rewrite is in scope.
