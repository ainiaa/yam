# T20 GUI updater source slice

Author: Jeff.Liu. Frozen engineering behavior for the next serial task; release configuration remains deferred by the user. This file does not authorize a current workspace writer or a real update request.

Use the already approved locked Rust updater SDK only. Add one visible Update settings entry in the real App, with current package version, configuration status, automatic-check preference and finite check/download/cancel states. Missing updater configuration is a normal unconfigured state: no plugin registration, extension lookup, network request or startup failure. Preserve the absent tauri.conf updater block and existing Cargo/lock/ACL/CSP. No fake endpoint, public key, platform, signature or release is added for activation.

Parse an exact bounded configuration whitelist before GUI-only registration. Require nonblank supplied key, 1–4 HTTPS endpoints (no userinfo or fragments), requireSignedVersion=true and allowDowngrades=false; reject unknown/insecure transport settings. A structurally supplied key is not a cryptographically validated key. The plugin verifies the signature and signed version only on actual SDK successful download. Unknown platform/build context stays unsupported. Background owner lifetime and state remain unchanged.

One GUI controller owns one operation, checked safe-integer generation, an exact SDK candidate and optional verified bytes. Custom YAM commands expose status/check/download/cancel/set-automatic-checks and a fail-closed install command. No arbitrary URL/header/key/package-path command inputs. State locks are never held across network await. Reject stale generations and duplicate starts before SDK access. Cancel and GUI exit fence publication, abort the exact worker, and join it before acknowledging completion or admitting replacement. Cancellation must have a truthful pending state if joining is not instant. Do not claim abort alone proves shutdown.

Configure the SDK HTTP client HTTPS-only for metadata and artifact redirects. Reject a returned non-HTTPS artifact URL. Check requests have a 15-second whole-operation acceptance/cancellation deadline; downloads a 120-second acceptance/cancellation deadline and an explicit SDK Update.timeout. At expiry, fence late success and show cancelling until the worker is joined; cooperative abort and synchronous SDK signature work do not guarantee physical exit at the deadline instant. Reuse Tauri's installed runtime and standard library; no direct Tokio/new downloader dependency, panicking callback, helper process or generic task framework. Completion must wake any deadline waiter so it does not accumulate idle threads. Timeout follows the same fenced abort/join cleanup.

Accept at most 256 MiB of observed artifact bytes, with checked arithmetic, and reject declared totals above that limit. Unknown or dishonest Content-Length does not bypass observed-size rejection. Callback overflow requests cancellation and no later SDK success can publish verified bytes. This is an artifact acceptance limit, not a strict heap/network pre-allocation limit; document this clearly. Transfer-finished callback never marks verified. Only SDK download Ok after its signature and signed-version verification can produce the verified state; an injected Ok only proves boundary mapping. No updater bytes, endpoint/key/signature/header/raw manifest or arbitrary SDK error reach the webview or localStorage.

Bound all DTO fields and exact object shapes. Current/release versions at most 128 UTF-8 bytes, plain-text notes at most 8192 bytes, fixed reasons, optional plain publication date, safe generation/progress integers. States: unconfigured, unsupported, idle, checking, upToDate, available, downloading, cancelling, verified, cancelled, error. Candidate/release/progress consistency is enforced. Installation is explicitly unavailable in every state, including a forged direct command and verified download: task admission, owner/parser version compatibility, data backup and supported release packages are a subsequent source slice. No installer invocation/restart/process exit.

Persist only an exact boolean automatic-check preference in a dedicated versioned localStorage record, default enabled. Read the preference before the single configured GUI startup check; missing configuration and opt-out cause zero calls. Reopening settings or React effect replay cannot duplicate that startup check. No recurring timer, owner auto-check, automatic download or installation. Status polling is bounded and only while the mounted settings observes a current operation. Actual component/App effects must fence unmount and stale success/error/finally and cancellation responses.

Strict TDD on real configuration gate/controller/command bodies with a test adapter; real App/component callbacks using the existing test conventions. Cover absent/invalid/unsupported configuration, no-update/available/failure, duplicate and stale intent, transfer-finish before signature failure, overflow/unknown total, timeout, cancel/late publication, abort+join ordering, startup opt-out/once-only, and zero installer calls. Do not copy a replacement controller into tests. Actual SDK network, signature integration, native package install and publication stay uncovered while the user-provided configuration is absent.
