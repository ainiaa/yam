# T12 bounded Git context

Author: Jeff.Liu. Date: 2026-10-03.

The active project/session header shows branch or detached HEAD, dirty/clean, canonical worktree and common Git directory. A directory outside Git remains usable. `get_git_context` is a semantic Tauri handler using the existing authenticated background Client, strict argument allowlist and dispatch; it does not create a second transport or start/restart an owner. No Git mutation, network, credential, hook trust, task or native package operation is added.

One owner-wide nonblocking query guard excludes concurrent Git queries without holding session/history/runtime locks. The actual App effect runs only the active directory, uses its document monotonic clock and five-second ticks, retains the original flight through cancellation, and rejects old project/owner/unmount replies. Failure also consumes the interval. Results update only when their values change. An owner epoch follows existing background gap/error events; it is not a new owner discovery mechanism.

## Execution boundary

The query shares a two-second deadline and cumulative 1 MiB budget across subprocess stdout/stderr and metadata snapshots. Child output uses bounded reads; timeout/overflow kills the owned Unix process group and returns a fixed code, including a parent-exited/descendant-held pipe. All fallible post-spawn setup, including Job attachment and pipe acquisition, goes through the same owned-child cleanup path. A test-only injected setup error proves that shared path kills/reaps the already started child within a bounded return. Windows uses the existing process Job helper but the actual Job API has not been tested on Windows. Files are bounded regular-file reads; unavailable, busy, timeout, overflow and unsupported states never become clean. Disk kernel stalls are not a hard realtime guarantee.

Safe original Git plumbing reads repository paths, branch/HEAD, effective configuration and index paths. All original commands disable fsmonitor/optional locks and hooks. Local/global/system/includeIf/worktree and configuration environment injection are checked for external clean/process drivers; such a repository is unavailable and no driver value is exported. Repository-steering environment variables are rejected. The installed executable is canonicalized to an absolute file before any repository cwd is applied, and literal argv are reused; no user command is accepted by this RPC.

Status runs in a newly created private shadow Git directory with fixed safe config, confirmed HEAD OID (or unborn ref), a bounded index snapshot and original objects. It does not load the original config/includes, global config, hook path or external filter drivers; lazy fetch is disabled. This isolated execution context prevents a newly introduced original filter from running between preflight and status. Rechecking original configuration/index/path identity/HEAD and known attributes validates the snapshot; the after-check is not the execution barrier. A changed snapshot becomes unavailable.

Finite builtin autocrlf/eol/filemode/symlinks/ignorecase settings and repository info attributes are retained. Explicit global attributes and known default XDG/HOME or `/etc/gitattributes` sources are unsupported rather than silently dropped. For at most 4096 known tracked paths, metadata-only `check-attr` compares original and private-shadow effective rules within the same query budget. A mismatch returns `git_attributes_unsupported`, so the installed Git’s arbitrary compiled system-attribute prefix need not be guessed. The controlled default-attribute fixture is not an actual system-prefix native acceptance. Unsupported object format/conversion settings and partial-clone/promisor configuration are unavailable before object-reading commands. Submodule worktrees are never entered: known top-level/staged changes may establish dirty, otherwise a gitlink repository reports submodule status unavailable. Cached-only diff includes staged gitlinks without inspecting the child repository.

The final file component remains unresolved so no-follow reads refuse links. Git’s documented [common-directory layout](https://git-scm.com/docs/gitrepository-layout) determines this fixed repository file. A nonempty effective `core.excludesFile` is explicitly unavailable (`git_conversion_unsupported`) for every configuration scope; no relative path, tilde, prefix or environment expansion is guessed.
