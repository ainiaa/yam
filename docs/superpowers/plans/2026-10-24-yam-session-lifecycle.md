# YAM 会话生命周期与退出修复

## 已批准行为

1. 存活会话连接原进程；选择、窗口恢复、标签恢复不启动新进程。
2. 已结束会话显示只读历史。“继续对话”恢复原生上下文；“再次运行”显式创建新任务。
3. 原生 ID 已知时精确续聊；绑定缺失时提供原生历史选择，不自动选择最近记录，不伪造空白恢复。
4. 状态栏常显 YAM 与任务内存；Codex 原生退出操作不得被 YAM 截断。提供清楚的应用停止入口。
5. 测量点击、创建返回、首帧与原生可输入阶段，原生权限等待单独记录。
6. 回归后构建、安装重启并验收；发布包须对应准确源码。公开发布及前轮大量改动的版本提交在材料可审阅后一次确认。

## 顺序与验证

- T1：恢复、停止、退出；先补现有 App 回调行为测试，统一共享入口。
- T2：已停止原生会话继续；覆盖可信 ID、绑定缺失、凭据／目录失效、重复点击与参数隔离。
- T3：内存常显、原生退出按键及显式停止；主／辅助窗口和窄窗口回归。
- T4：离线启动计时与当前配置实测；不调用真实厂商，不自动批准钩子。
- T5：版本、源码、更新元数据和候选材料一致。
- T6：完整回归、独立复核、安装后界面验收。无法验证的分项说明，不把后台帧当作画面通过。

不新增依赖，不改变全局 Codex 配置、MCP／skills／插件资源及 ChatGPT Desktop。当前运行任务不在测试中停止；最终重启若涉及运行任务，先完成候选再确认影响。
