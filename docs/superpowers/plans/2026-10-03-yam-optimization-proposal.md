**状态：待用户审核；仅授权编写方案，尚未授权实现。**

目标：把现有跨平台 Agent 会话底座优化成可长期使用、可追溯、方便并行开发的本地工作台。保留用户现有 CLI、订阅、权限与模型配置。

## 1. 推荐路线与备选

| 路线 | 内容 | 收益 | 代价 | 建议 |
|---|---|---|---|---|
| A：先可靠性，再效率，再发布 | 数据容量、恢复与性能 → 项目配置/Git → 分屏/CLI → 发布 | 每批有独立价值，保护已有工作流 | 新功能展示较慢 | **推荐** |
| B：先对齐 cmux 的可见功能 | 优先分屏、浏览器、SSH、Teams | 短期展示能力丰富 | 验收范围和维护成本快速增加，容量问题仍存在 | 不作为首轮路线 |
| C：先统一结构化 Agent 客户端 | 以各 CLI 的 server/app-server 接口重做交互 | 审批、消息和 diff 更容易产品化 | 改动交互架构，协议和版本维护负担大 | 只在后续独立试验 |

选择 A。不更换 Tauri/Rust/React/xterm，不新建插件平台，不引入数据库、云服务或模型 API 调用。Git、文件操作和配置优先使用现有依赖与标准库。自动更新可能需要官方插件，列为实施前的显式依赖决策。

## 3. 必须保持的行为契约

1. 启动应用、读取历史、通知点击、后台重连均不得自动重跑 Agent。
2. 回复结束、进程退出、系统接受通知、用户已读是不同事实。
3. 不覆盖用户原 Hook、模型、审批、沙箱和原生 CLI 配置。
4. 无可靠事件、身份或平台能力时明确降级，不猜测完成。
5. 前端是视图，后台是任务和终端状态所有者；后台故障不能静默替换为新任务。
6. 输入接管必须显式；部分输入被接受后不得整段自动重发。
7. 活跃任务、未读回执、待发送通知和唯一未保存场景不得被清理策略删除。
8. 新依赖、正式发布、永久删除和 Git 破坏性操作不由方案审核笼统授权。
9. 每项 feature/bugfix/refactor 测试先行，覆盖正常、边界、异常；没有可执行验证不能算完成。

## 6. B1：历史容量和数据生命周期

### T03：容量展示与历史列表分页

**结果：** 大历史不要求界面反复传输完整记录，容量接近预算时有明确提示。

**范围：** `lib.rs` 的 HistoryStore/list_sessions、`background.rs` RPC、`App.tsx`、`SessionLogSearch.tsx`、相关测试；按职责提取 `src-tauri/src/history.rs`，不移动无关会话逻辑。

**设计：** 保留现有 JSON 存储，新增分页摘要接口，默认每页 100 条，上限 200；摘要不携带完整收件箱/日志。活动会话和未读统计独立有界查询；详情按 ID 读取。分页游标绑定历史 revision，变化时要求重新加载，避免翻页重复或遗漏。容量达到 24 MiB 提醒，32 MiB 的现有硬保护保持。占用统计区分元数据、日志、场景、备份及归档，后台执行有界扫描且支持取消。

**测试先行：** 0/1/100/101 条、1 万条分页、并发状态更新、游标过期、非法 page size、Unicode 搜索、取消与 I/O 失败；保留未读跳转和最新响应优先回归。

**验收：** 初始列表只取一页；逐页遍历与快照记录集合一致；后台状态变化不把旧页覆盖新页；靠近预算时提示可操作的归档入口。分页改善传输与渲染，不能宣传解决 JSON 全量保存成本。

### T04：可恢复的归档与还原

**结果：** 历史可移出热数据而不丢日志、场景、通知定位和续聊身份。

**范围：** `history.rs`、`session_logs.rs`、`background.rs`、`lib.rs`、`App.tsx`；新增历史归档界面及测试。

**设计：** 仅允许 `succeeded/failed/stopped` 且无未读、待发通知、活跃 resume claim 的记录归档；`needs_attention` 不自动归档。数据仍在应用私有目录，归档不压缩、不删原生 CLI 对话。后台独占写入，使用分片归档与有界清单；每个分片不超过现有 32 MiB 读取预算，清单分页，不能创建另一个无限大 JSON。日志/场景优先保留原路径，减少跨文件移动。

归档通过“写入并同步分片 → 写事务记录 → 原子更新热历史 → 完成事务”执行。启动按事务状态恢复，按 session ID 去重；每个故障点保证热历史或归档至少有一份完整可读副本。还原先核对热预算，超过预算拒绝并保留归档。新后台支持按 ID 查归档；旧客户端不获得写权限，协议不兼容时明确提示升级。

**验收：** 各事务点注入退出/保存失败，重启后无丢失和重复；归档前后 Unicode 搜索、场景、名称、通知 ID 定位、原生续聊校验一致；拒绝活跃/未读/未知记录、符号链接、超限分片和损坏清单；归档后热元数据体积下降。

### T05：保留策略与显式永久清理

**结果：** 用户能管理长期磁盘占用且清楚知道删除什么。

**默认：** 自动永久删除关闭；自动归档也默认关闭。可选自动归档“已结束、全部已读且超过 30 天”，仅在后台空闲时执行小批量。永久删除只能对归档记录发起，预览条数、时间、字节和范围，再由用户确认；不删除原生 Agent 的历史。触及任何运行、未读或待通知数据时拒绝。

**设计：** 用户确认后先以私有事务暂存方式标记删除，后台恢复未完成事务并保留可诊断记录；只删除已验证属于目标 session 的文件，不按用户输入拼接路径递归删除。清理 localStorage 名称引用时不得影响其他记录。磁盘不足、权限失败不破坏剩余数据。

**验收：** 默认长期运行不删除数据；自动归档筛选边界、UTC 时间存储与本地时间展示、并发收到通知、删除中断与失败均有回归；预览和实际删除集合一致；取消无变化。

**数据库反转条件：** 如果归档后的热集合仍不能满足保存/查询目标，先记录解析、序列化、fsync 的分量；只有 JSON 被确认是主要瓶颈时，再单独提交 SQLite 迁移方案与依赖审批。不将迁移塞进 B1。

## 7. B2：终端性能、恢复与原生验收

### T06：固定当前版本的可重复性能基线

**结果：** 内存、切换和输入成本可对比，不依赖一次峰值或截图。

**范围：** 现有 `scripts/yam-memory.py`、`terminal-renderer-memory.py`、`background-platform-smoke.py`、终端探针；新增合成切换/输入延迟脚本和 `docs/evidence/` 记录。

**场景：** 冷启动；1/4/16 会话；16 个持续输出 30 分钟；停任务；活跃任务下退出/重开 GUI；100 次快速切换；ANSI/TUI/中文/emoji/大粘贴；已结束场景切回。固定构建类型、窗口尺寸、历史、输出夹具和采样归属，各短测至少 3 轮。

**指标：** 完整样本比例、总/组件内存中位数和峰值、CPU、输入到可见回显、warm/cold 切换 p50/p95、输出队列与场景字节。自动脚本与原生键鼠实测分开；测量记录绑定提交和包 SHA256。没有完整样本的测量不当作通过。性能采样不输出真实 argv/env/prompt。

### T07：只优化已测出的投影/恢复瓶颈

**结果：** 保留终端语义的前提下，降低实际测出的刷新或重开成本。

**范围：** `App.tsx`、`terminal-frame.ts`、`terminal-views.ts`、`terminal_runtime.rs`、`terminal-service.cjs` 和现有测试。

**优先顺序：** 先去掉重复/过期帧读取与未变化数据传输，合并同一会话更新；再处理可验证的后台/前台重复场景；最后才考虑增量投影。沿用 revision/instance/viewport/lifecycle 校验，活动终端保留尺寸同步和输入租约。不得为降低内存随意释放 live 视图、强制 GC、缩短已批准的 scrollback 或减少正确性校验。私有 xterm 光标字段封装在现有投影边界，升级必须跑版本契约探针。

**验收：** 同机固定负载至少 3 轮；所优化指标目标改善至少 15%，且其他关键延迟相对基线 p95 不回退超过 10%。若无稳定收益，保留基线和原实现，不交付复杂缓存。建议 warm 切换 p95 ≤150ms、ended cold restore p95 ≤2s；输入到可见回显 p95 ≤100ms。以上是本地合成负载验收目标，不是对任意 Agent/机器的承诺。若 T06 证明目标不可达，先提交测量和范围调整，再改执行契约。

**必须通过：** alternate screen、pending-wrap、查询唯一应答、Unicode 跨块、选区不被覆盖、viewport、输入背压/取消、重连旧帧失效、保存失败保留唯一场景。

### T08：补齐原生恢复与通知验收矩阵

**结果：** 对每个平台明确哪些完整使用流程实际通过。

**场景：** 新建/输入/粘贴/选择/复制、鼠标 TUI、缩放与切换、普通关闭与正常退出、重开保留同一任务 PID、后台崩溃不自动重跑、Take control、三真实 CLI 并行双轮、前台抑制、后台通知、权限关闭后恢复、点击通知/冷启动。

**设计：** 默认使用隔离包身份和合成 PTY，真实 CLI 使用公开合成提示，不复用真实项目任务。临时 Hook 信任、通知或辅助功能权限只有用户明确授权才操作，并记录恢复结果。Windows/Linux 无可用交互桌面时列为验收例外，不阻塞不相关优化，不重复申请已经暂缓的事项。

**验收：** 每条有平台、提交、包身份、步骤、期望/实际结果和原始回执；平台未验收能力不进入正式支持宣传。流程通过后保持同一版本回归，不能拿旧构建点击结果代替新架构结果。

## 8. B3：项目配置与日常操作

### T09：项目启动配置和模板

**结果：** 选择项目即可复用 Agent、模式、参数和常用任务模板。

**范围：** `workspaces.ts`、`App.tsx`、后台启动验证；新增 `src/project-config.ts` 及测试。

**设计：** 应用私有全局偏好与可选项目 `yam.json`，版本为 1；优先级“本次界面输入 > 已信任项目配置 > 全局默认”。只支持已有 Agent 和普通 custom command，不创造 Adapter DSL。未知版本、字段、非法参数显式报错。仓库配置首次加载只预览，用户批准后才能影响启动；启动始终由用户明确发起。文件内容摘要变化后重新批准；信任不跟随同名目录。

环境配置首轮只支持引用当前进程已有变量，拒绝 YAM Bridge/token/launch identity 等内部保留变量；不将秘密值落盘，不自动读取 `.env`，不把变量展开进 shell 命令模板。项目移到另一台机器时重新校验目录与可执行文件。

**验收：** 配置优先级、未信任/变更后配置、恶意命令不自动执行、变量缺失、重复模板名、CLI 不存在、取消启动和字面参数均有回归；配置错误不改全局 CLI 设置。

### T10：终端偏好与会话导航

**结果：** 字体/字号/主题可设置，常用操作容易找到。

**范围：** `App.tsx`、`App.css`、`workspaces.ts`、`agent-events.ts`；新增 `src/TerminalSettings.tsx` 和测试。

**设计：** 使用 xterm 现有 options；字号 10–24、有限内置主题、字体字符串限制长度并禁止控制字符。不导入 Ghostty 配置。应用内命令面板提供新建、切换、搜索、收件箱、恢复、诊断和设置，复用已有动作；快捷键与 IME/对话框输入不冲突。支持 session pin 与关闭已结束视图，关闭视图不删除历史。Run again 与 Continue conversation 用可见文案区分。

**验收：** 偏好重启后保持；非法/损坏配置回退有提示；字体/字号变化正确同步终端尺寸；对话框/IME/文本输入不触发快捷键；停止/重跑等有副作用操作不被仅搜索动作触发。

### T11：系统托盘与全局唤起

**结果：** GUI 关闭后有明确入口查看任务并重新打开。

**范围：** `lib.rs`、`background.rs`、Tauri 配置、前端设置与平台回归。

**设计：** 使用 Tauri 原生能力，默认关闭系统全局快捷键；只允许用户显式启用且显示注册冲突。托盘只显示状态计数、打开窗口、暂停通知和显式 Stop all tasks and quit，不从菜单执行任意命令。后台托盘注册不得冲突于 GUI 的系统身份或影响 idle 退出条件。若平台托盘不受支持，保留正常窗口入口并说明限制。

**验收：** GUI/owner 生命周期中只有一个托盘身份；停止/退出结果与现有契约相同；快捷键冲突和取消注册可见；系统不支持时不影响任务。需要新增插件或 crate feature 时先列出具体变更，按依赖约束确认。

## 9. B4：Git 上下文与 worktree

### T12：只读 Git 状态

**结果：** 项目/会话显示分支、dirty 状态、worktree 路径和仓库关系。

**范围：** `workspaces.ts`、项目侧栏、后台 RPC；新增 `src-tauri/src/git_context.rs` 和真实临时 Git 仓库测试。

**设计：** 用字面 argv 调用已安装 Git，使用机器可读输出；仅活动项目轮询，每个仓库最多一项在途查询，间隔不少于 5 秒，结果变更才更新 UI。截止 2 秒、输出上限 1 MiB，超限/超时为“状态不可用”，不能显示 clean。非 Git 目录正常使用。支持 detached HEAD、linked worktree、空仓库、空格/Unicode 路径。PR 查询列为后续，不添加网络凭据和 GitHub 自动调用。

**验收：** 正常/dirty/detached/unborn/worktree、Git 缺失、非仓库、非法路径、超时、旧响应覆盖新选择等有回归；查询不改索引/分支/文件。

### T13：显式创建隔离 worktree

**结果：** 并行任务可以在独立目录运行，减少共享工作区冲突。

**设计：** 首轮只支持用户主动创建并启动，分支默认 `codex/yam/<session-id>`，基于用户可见且确认的本地 ref。现有未提交修改不自动复制；界面展示该限制。新目录、分支占用、Git 锁、磁盘失败、会话启动失败均有状态记录；失败后预览残留供用户选择保留或安全清理，不删除用户已有目录。

清理仅限 YAM 创建、无活动会话且 clean 的 worktree，显示预览并由用户确认；dirty 时拒绝，不用 `--force`。不做 commit、push、merge、reset，不把关闭终端等同于清理 worktree。submodule/嵌套仓库首轮拒绝自动管理并给出说明。

**验收：** 两 Agent 使用不同目录；不存在分支与已占目录不被覆盖；dirty 和活动 worktree 拒绝清理；启动失败保留可恢复记录；重启后仍能识别 YAM 管理范围。

## 10. B5：分屏与布局

### T14：两到四个终端分屏

**结果：** 同时观察/操作多个任务，单个终端状态保持独立。

**范围：** `App.tsx`、`App.css`、`terminal-views.ts`、`terminal-frame.ts`、输入/通知上下文 RPC；新增 `src/TerminalLayout.tsx` 与布局测试。

**设计：** 固定支持横/竖 2 屏与 2×2 布局，最多 4 个可见 pane，不先实现任意递归布局和拖拽树。同一 session 只出现在一个 pane。每个 pane 有自己的尺寸、revision、viewport 和渲染状态；键盘输入只给焦点 pane，不提供广播输入。关闭 pane 不停止任务；停止任务为独立动作。焦点 pane 与可见 pane 区分，前台通知只抑制实际焦点会话。

**验收：** 两/四会话唯一归属，鼠标/键盘/Unicode 输入不串路由；resize 与后台尺寸一致；切换/收起/关闭不丢场景或停止任务；非焦点 pane 需要介入仍能提醒；长测包括 4 个同时输出的可见 pane。

### T15：布局保存和恢复

**结果：** 重开窗口恢复 pane 排列、选中任务和焦点提示。

**设计：** 仅保存 session ID、布局类型、pane 顺序和选中项，不保存可执行命令。不恢复已消失的会话为新任务；显示空位或只读历史。配置版本化，损坏/未知版本安全回到单屏并提示。断开后重新绑定已确认的同一后台；owner 更换走现有失效路径。

**验收：** 运行/结束/归档/不存在/损坏场景恢复；重开不新增进程；布局恢复与通知点击的目标选择互不覆盖；窗口过窄时可访问所有 pane，键盘焦点和 aria 标识明确。

## 11. B6：最小公开 CLI 与事件接口

### T16：稳定的本地控制命令

**结果：** 用户和 Agent 可在终端查询、创建、选择和停止明确的 YAM 会话。

**范围：** `main.rs`、`lib.rs`、`background.rs`、`agent_bridge.rs`；新增 `src-tauri/src/cli.rs`、CLI 测试与 `docs/yam-cli.md`。

**首轮命令：** `yam status --json`、`yam sessions list --json`、`yam session show <id> --json`、`yam session start --project <path> --adapter <id> --mode <mode> --prompt-file <path>`、`yam session focus <id>`、`yam session stop <id>`。默认只连接既有 owner，不启动 GUI/后台；只有显式 `session start --start-owner` 可以创建后台。读取命令不修改任务。

**设计：** 复用现有可执行文件的非 UI 入口，打包提供同一二进制的命令入口，不依赖开发环境 PATH。不暴露内部连接描述符或 token，不增加公网 listener；本机当前用户认证、协议版本、命令白名单、消息上限和截止保持。退出码明确区分业务拒绝、连接失败和非法参数；stdout 为结果，stderr 为脱敏诊断。启动幂等 request key 由调用者显式提供或当前进程生成，不对未知响应盲目重跑。CLI 不自动取走输入租约。`focus` 在没有已连接 GUI 时返回明确错误，不为聚焦偷偷启动窗口；重新打开应用仍走用户已有系统入口。

**验收：** 三平台实际包调用、非法/未知 ID、错误 owner 身份、超限、目录不存在、CLI 缺失、重复 start 和失去响应回执均有测试；查询/聚焦不重跑；prompt 文件按 UTF-8 有界读取，内容不进入诊断。

### T17：可重连的脱敏事件订阅

**结果：** 自动化可监听状态和需介入事件，无需频繁轮询完整历史。

**命令：** `yam events --json --cursor-file <path>`；首轮事件仅 session lifecycle、agent phase、receipt state、integration status 和 gap。

**设计：** 复用有界事件 relay；游标绑定 owner instance。断线在同一实例内有限重连；溢出输出 gap，需要消费者读取状态快照；新 owner 明确实例变化，不静默拼接。默认无 prompt/tool payload、终端输入、日志全文、凭据和原生 ID。订阅不建立 CLI 输入租约。慢消费者有有界缓冲，不能阻塞所有任务；显式 Ctrl+C 结束。

**验收：** 顺序/去重/游标重用/owner 替换/慢消费者/断线/gap、合成敏感内容不外泄；订阅不会启动 Agent 或改变前台通知策略。公开 v1 契约文档和兼容测试一起交付。

## 12. B7：分发与更新

### T18：发布前安全和元数据收口

**结果：** 发布配置与许可、文档、能力声明一致。

**范围：** `tauri.conf.json`、capabilities、Cargo 元数据、README、第三方 notices；新增发布检查与安全配置回归。

**设计：** 根据生产实际资源/IPC 加最小 CSP，不照抄允许任意来源的模板；验证开发配置独立。核对 opener/deep-link/dialog 的范围，网页或通知内容不能借 URL 执行任意命令。修正模板描述和作者元数据为 Jeff.Liu。项目许可由权利人选择，未经选择不生成 LICENSE；第三方许可仍完整打包。版本和 changelog 与产物一致。

**验收：** 原生 WebKit 正常启动，必要 IPC/样式/字体可用；违规资源与脚本被阻止；deep-link 未知/伪造 ID 拒绝；依赖 notices 不缺失。CSP 是加固任务，不将审查中未证实的漏洞写成已修复。

### T19：正式构建、签名与安装验收

**结果：** 可分发产物与测试包区别明确。

**设计：** macOS 复用现有签名/公证脚本；Windows 安装包与签名走平台流程；Linux 验证实际安装/卸载、资源布局与通知后端能力。debug 包不能代替 release 测量/验收。CI 凭据仅来自受保护的 secrets，不写入源码和报告。保留构建提交、依赖锁、校验和、支持平台/架构和安装回执。

**验收：** macOS 签名、公证、staple、Gatekeeper；Windows 安装/启动/卸载/签名检查；Linux 实际 deb 安装/启动/卸载。机器、证书不可用时只完成流程和可执行检查，正式分发项为 blocked/excluded，不用测试签名冒充。上传公证、GitHub Release 与外部发布必须另有明确授权。

### T20：安全自动更新

**结果：** 更新失败可恢复，活跃任务不会因后台版本切换被误重跑。

**前置决策：** 确认官方 Tauri updater 所需新增依赖、发布平台、签名密钥持有人和更新元数据地址；方案通过本身不创建密钥或配置外部服务。

**设计：** 默认提示有新版，由用户选择下载/安装；校验签名和版本，错误包不执行。更新前核对 GUI/owner/parser 协议兼容。活跃任务存在时首轮延迟安装，明确告知原因；不强停任务、不中途替换后台或正在使用的解析器。用户可关闭更新检查。迁移前备份，失败时保留旧数据和明确恢复路径；不宣称不支持的自动二进制回滚。

**验收：** 无更新、合法更新、错误签名/版本、断网/取消/磁盘不足、活跃任务阻止安装、协议不兼容、历史迁移失败均有测试；release 原生安装验证。平台插件不支持的格式采用明确手动升级路径，不做伪自动更新。

## 13. 后续选项：不计入 B0–B7 的完成条件

| 选项 | 触发条件 | 推荐最小范围 | 不提前做的部分 |
|---|---|---|---|
| OpenCode 原生续聊 | 用户确有停止后继续需求且原生身份可核验 | 单 Adapter、原目录与 root 校验、显式 resume | 不把 `/new` 切根伪装为原会话 |
| 审批/问题卡片 | 经常返回终端处理介入，官方协议可可靠应答 | 先一个 Agent 原生协议、超时回 CLI | 不关闭原生权限、不用文本猜审批 |
| PR/diff 上下文 | Git/worktree 已稳定且用户要求 | 先外部打开 diff/PR，再只读摘要 | 不隐式发消息、创建 PR 或持有新凭据 |
| 内置浏览器 | 频繁切换浏览器且可测出价值 | 一个受限预览 pane | 不先做 cookie 导入、任意 JS 自动化 |
| SSH 远程工作区 | 有明确远程任务和恢复需求 | 先依赖用户已有 SSH 配置的单主机方案 | 不做云 VM、账号、跨用户服务 |
| 自定义 Adapter | 除三内置 Agent 外有稳定使用需求 | 可声明降级能力的少量配置字段 | 不建通用插件市场和任意动态代码框架 |
| 费用/token 面板 | CLI 有可信计费数据且用户要求 | 标注来源与缺失状态 | 不从文本估算并宣称真实费用 |

这些选项需要各自的设计和授权，不因“对比 cmux”就全部实现。

## 14. 统一测试与闭环方式

每个任务按以下顺序执行，不以“代码写完”代替交付：

- [ ] 核对当前基线、现有测试和图谱定位，冻结该任务唯一可验证结果。
- [ ] 明确接口、owned paths、前置任务、行为变化、数据/权限边界。
- [ ] 先写正常、边界、异常测试，运行并记录失败原因。
- [ ] 最小实现，复用项目模式，不引入无实际需要的抽象。
- [ ] 运行定向测试，确认原失败场景转绿。
- [ ] 执行相关平台、回归和静态检查。
- [ ] 审查状态/并发/文件/输入路由/安全影响；有缺陷则补回归再修。
- [ ] 更新当前能力表、验证提交、命令、产物摘要和例外。
- [ ] 报告该任务结果及下一步；仅进入已授权的后续范围。

共同验证命令：

```sh
# 仓库根目录
rtk cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml -- --check
rtk cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
rtk cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --locked -- --test-threads=2
rtk python3 -m unittest discover -s scripts -p 'test_*.py'
rtk git diff --check

# apps/desktop 目录
rtk pnpm test:coverage
rtk pnpm build
rtk pnpm tauri build --debug
```

首次基线与批次收口跑完整相关检查；任务中只跑有意义的定向验证，新变化/失败再扩大范围。平台检查沿用 `.github/workflows/ci.yml`，CI 构建不替代真实 UI、安装、签名和通知验收。测试计数可变，记录实际结果，不把固定数量作为目标。

每批状态只能为 planned/running/verified/blocked/excluded；excluded 写明具体原因和支持声明影响，不算 verified。有限范围完成不等于外部发布完成。代码保留在当前授权工作区；commit/push/merge/发布分别遵守用户授权，方案不自动授权 Git 写历史。

## 15. 发布闸门、风险与回滚

| 风险 | 防护 | 不通过时的处理 |
|---|---|---|
| 归档/清理数据丢失 | 单 owner、原子保存、事务恢复、候选预览、故障注入 | 关闭自动策略，恢复备份，保留原始证据 |
| 配置文件变为命令执行入口 | 摘要绑定信任、显式启动、字面 argv、保留变量拒绝 | 配置不应用，仍可手工启动 |
| worktree 清理误删修改 | 管理范围验证、活动/dirty 检查、显式确认、禁 force | 拒绝清理，保留目录 |
| 分屏串输入/误抑制通知 | 单 session 单 pane、焦点路由、每 pane 版本和尺寸 | 回到单屏；不停止任务 |
| CLI/API 扩大攻击面 | 本机认证、白名单、协议版本、有界数据、脱敏 | 关闭公开入口，保留 GUI |
| 性能优化破坏 TUI | 固定探针、真实延迟/场景对照、不删除正确性校验 | 保留原实现和测量记录 |
| 更新替换活跃 owner | 活跃任务时延迟安装、协议验证、迁移备份 | 保留旧版，提供明确手动恢复 |
| 平台验收资源不足 | 区分自动化和实机，例外影响支持声明 | 不宣传该平台能力已正式通过 |

版本回退前核对数据格式；新增数据不得由不理解它的旧版本覆盖。归档、项目配置、布局、CLI/事件契约均有版本字段和兼容规则。未知版本拒绝写入；迁移保持旧备份，恢复步骤由测试证明。回滚不是无条件 `git reset` 或删除用户数据。

## 16. 整体完成标准

推荐范围完成需要 B0–B7 的已授权任务各自有验收结果，并同时满足：

1. 容量增长有用户可操作的归档/清理路径，受保护的数据不会自动删除。
2. 历史、场景、原生续聊身份和通知定位跨归档/恢复保持一致。
3. 现有 Agent 轮次语义和后台连续性不回退。
4. 项目启动配置、Git/worktree、分屏、CLI 均可独立使用且有三平台相关验证。
5. 性能报告绑定最终实现；改善有重复测量依据，限制公开。
6. 正式分发/更新通过对应平台门槛；无法执行的部分明确保留，不混称完成。
7. 没有同范围已确认缺陷未处理；资料、测试、代码行为一致。

## 17. 用户审核时需要看的选择

以下均为方案建议，尚未替用户作出授权：

| 项目 | 推荐 | 对实施的影响 |
|---|---|---|
| 首轮批准范围 | 先 B0–B2，再确认后续；或一次批准 B0–B7 | 控制执行长度，不改变逐任务验收 |
| 数据保留 | 默认不自动归档、不自动永久删除 | 先交付安全手工能力 |
| 数据存储 | 先保留 JSON，测量证明不足再讨论 SQLite | 不新增数据库依赖 |
| 分屏范围 | 最多 4 pane，固定布局 | 有完整价值，避免递归布局工程 |
| 项目配置 | 仓库配置首次/变更必须确认后才影响启动 | 保留安全与可分享模板 |
| 并行开发 | worktree 为用户显式选择 | 不擅自改变现有目录行为 |
| 自动更新 | 默认提示、用户安装，活跃任务延迟 | 保护后台任务 |
| 开源许可 | 由权利人选择后进入 T18 | 不在方案阶段写许可证 |
| 扩展功能 | 浏览器/SSH/审批卡片等另立方案 | 首轮不扩张成全能 IDE |

审核通过后，第一个实施任务是 **T01：当前能力清单**，随后 T02；在用户授权的范围内按 B1→B2→B3→B4→B5→B6→B7 顺序闭环。仅新依赖、不可逆操作、外部发布或冻结范围实质变化需要再次确认，不为普通实现细节反复打断。
