# YAM 本地工作流优化计划

作者：Jeff.Liu · 2026-10-26

## 目标与边界

保留官方 CLI 的执行、配置优先级、推理参数与原生会话恢复。YAM 只补齐可见性和本地工作流，不实现模型调用循环，不改现有会话协议。沿用已批准的 CodeMirror 选型和现有文件读写、Git 安全边界，不引入 IDE 服务或中间件。

所有步骤串行，每步先补失败测试，再修改和验证。现有未提交改动作为基线保留；不提交、不发布、不创建新应用身份。无界面测试不得间接启动浏览器或其他桌面应用。

## 执行顺序与验收

| 步骤 | 可验收结果 | 实现与验收边界 |
|---|---|---|
| 1 运行信息 | 当前会话能查看 CLI、原生会话 ID、配置和推理参数来源、Hook 状态 | 复用实际已有元数据；未确认的有效模型/配置明确显示未知；只展示密钥来源、不展示值；覆盖旧历史和异常元数据 |
| 2 本轮变更 | 用户能建立开始基线，查看开始后产生的文本差异 | 有界、只读快照；保留已有脏修改；同文件后续编辑能比较；并发/人工修改明确归因不确定；不写索引、不 stash/commit/reset；失败不影响 CLI |
| 3 轻量编辑 | 本地文本编辑具备行号、语法高亮、查找替换、多文件标签和草稿恢复 | CodeMirror；沿用版本校验和原子保存；外部修改提示；缓存有界且仅在本机；不覆盖冲突文件；Windows 不支持时明确提示 |
| 4 审查反馈 | 差异能定位编辑文件，审查意见可由用户明确发送至原会话 | 复用原终端输入路径；不隐式提交、不启动或恢复其他会话；历史/断开/目标变化时阻止误发；文本作为输入，不当作命令执行 |
| 5 交付检查 | 支持边界可见，打包可验证主程序与后台 helper 一致 | 复用已有打包；验证版本、标识、资源和签名；保留旧历史启动/恢复兼容性；不更改产品标识和发布版本 |
| 6 性能与联合回归 | 取得可复现的无界面性能基线，完成整体验证 | 复用吞吐/积压/隐藏会话/内存测试；记录环境和测量边界，不声称已验证真实屏幕绘制；运行前后对照、前后端回归、覆盖率与独立复核 |

本轮基线第一版由用户显式开始记录，先保证已有修改和并发编辑的边界可靠；不在官方 CLI 的每次按键或 Hook 回调中插入阻塞快照。草稿恢复须在保存前重新核验磁盘版本。发送审查反馈需用户在界面中操作，禁止自动向正在执行的 Agent 插入意见。

## 暂不实现

SSH 文件工作区、LSP/调试器、云端任务、团队平台、Office 预览、自动 hunk 撤销和自研 Agent 核心。本轮不切换到 Pi/OMP 运行内核。命令块仍依赖现有可信边界，不以终端文本猜测任务完成。

## 验证方式

每步记录源码边界、失败/通过证据和复核结论。前端使用 Node 单元及现有组件测试，后端使用隔离 HOME 的 Rust 测试；官方 CLI 兼容性使用现有回环模拟服务。最终运行构建、前后端回归、原生覆盖率、打包检查。真实浏览器/GUI 自动化测试保持禁用，不将跳过项视为通过。

T4 提交边界：反馈经确认填入原 CLI 输入区，复用终端粘贴与 FIFO 写入；YAM 不发送 Enter，提交沿用原 CLI 交互。
