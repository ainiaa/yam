# YAM 产品与实现计划

作者：Jeff.Liu。本文保留目标与里程碑作为路线图；当前声明以 [当前能力清单](yam-capability-matrix.md) 为准（源码基线 `6b00a7d`）。历史阶段完成不等于当前版本三平台原生验收。

## 1. 产品目标

YAM（Your Agent Mission Control）是一款面向 AI 开发者的跨平台桌面工作台，用于管理 Codex、Claude Code 等 CLI coding agent 的并行任务、终端会话和完成通知。

YAM 的核心承诺：

1. **通知可靠**：任务真正进入完成、失败或需要用户介入的状态时才通知，避免重复通知和“假完成”。
2. **运行稳定**：前端界面、终端渲染和 CLI 进程相互隔离；单个任务崩溃不能拖垮整个应用；状态可恢复。
3. **操作简单**：打开应用即可创建工作区和任务，不要求用户理解 tmux、PTY、IPC 或 CLI 适配细节。
4. **跨平台**：第一版覆盖 macOS、Windows、Linux，优先保证核心行为一致，再适配平台通知和快捷键差异。
5. **CLI 兼容**：通过适配器支持 Claude Code、Codex，并允许用户配置其他命令行 agent。

## 2. MVP 范围

### P0：第一条可交付闭环

- 创建一个本地工作区并选择工作目录。
- 启动一个 CLI 会话，默认使用系统 shell，也支持传入自定义命令。
- 在内置终端中实时显示 stdout/stderr 和退出状态。
- 显示运行中、成功、失败、已停止四种明确状态。
- 用户主动停止、进程自然退出、进程异常退出均能正确收敛到终态。
- 任务进入终态后触发一次桌面通知；应用窗口不在前台时通知更明显。
- 关闭并重新打开应用后，历史任务记录仍可查看。

### P1：可靠性与效率

- 多会话并行运行，单会话互不影响。
- 会话心跳、无输出超时提示、进程树清理和孤儿进程回收。
- 应用重启后的会话恢复策略：可恢复、已结束、状态未知三类。
- 任务筛选、搜索、重命名、复制日志和重新运行。
- Claude Code、Codex 的命令探测、参数模板和完成状态识别。

### P2：跨平台与可扩展性

- macOS、Windows、Linux 安装包和自动更新通道。
- 自定义 CLI adapter 配置、环境变量管理和项目级默认设置。
- 全局快捷键、系统托盘、通知操作按钮。
- 崩溃报告、诊断日志导出和版本升级迁移。

## 3. 非目标

- 第一版不实现远程开发环境、云端任务编排或账号系统。
- 第一版不替代 Claude Code、Codex 等 agent 的模型和权限管理。
- 第一版不内置代码编辑器；代码编辑继续使用用户偏好的 IDE。
- 第一版不承诺在没有对应 CLI 的机器上模拟 agent 行为。

## 4. 技术方案

### 桌面层

- **Tauri 2**：负责桌面窗口、安装包、系统通知和平台集成；托盘仍是路线图项。
- **Rust 核心**：负责会话生命周期、PTY/子进程管理、状态机、日志落盘和 IPC 命令。
- **React + TypeScript**：负责工作区、任务列表和终端交互界面。
- **Node 26.10.0 + xterm 6.0.0 / serialize 0.14.0**：后台持久解析器持有终端状态；前台 xterm 显示投影、接收输入，认证 IPC 连接独立 owner。

### 数据与状态

- 当前使用 `sessions.json` 保存会话元数据及 Agent 回执，原子替换并保留可恢复备份；项目及界面偏好存于前端 localStorage。早期 SQLite 设想未实施，迁移需另行设计和依赖确认。
- 终端输出按有界日志写入文件，结束会话另存最终场景；32 MiB 历史元数据、8 MiB 单日志、2000 行解析器滚动历史和 16 个前台视图的边界见当前能力清单。尚无用户可操作的归档/清理闭环。
- 所有状态迁移通过显式状态机完成，禁止根据 UI 文本猜测任务状态。
- GUI 退出保留活跃任务，显式 **Stop all tasks and quit** 停止全部任务；无活跃任务的 owner 在 60 秒无客户端请求后退出。重开、历史和通知点击不重跑 Agent；后台丢失后的遗留运行态为 `needs_attention`。

### 核心状态机

`created -> starting -> running -> {succeeded, failed, stopped, needs_attention}`

每次状态变化包含会话 ID、原因、时间戳和进程退出信息。通知器只消费状态事件，并按事件 ID 去重。

## 5. 里程碑与验收

### M0：工程基础

- Tauri 2 + React + TypeScript 项目可启动、可构建。
- Rust 核心与前端 IPC 通道打通。
- 单元测试、集成测试、格式化和 lint 命令固定下来。
- 产出：基础应用窗口、版本信息命令、CI 骨架。

### M1：单会话纵向切片

- 从界面创建会话，Rust 启动 PTY，xterm.js 实时显示并可输入。
- 进程正常退出、非零退出和用户停止均能正确显示终态。
- 产出：第一个可操作的 YAM alpha。

### M2：稳定性底座

- 进程监督、超时、孤儿进程回收、日志持久化和应用重启恢复。
- 注入模拟 CLI 进行故障测试：启动失败、突然退出、持续无输出、输出爆量。
- 目标：核心会话测试通过率 100%，状态事件无重复或丢失。

### M3：通知系统

- 完成、失败、需要用户介入分别使用明确通知内容。
- 通知去重、前台抑制策略、通知点击回到具体会话。
- 目标：自动化场景通知准确率 >= 99%，同一事件最多通知一次。

### M4：CLI 适配器

- Claude Code、Codex 内置适配器和通用自定义命令适配器。
- 能力探测、命令模板、退出码和交互输入策略可配置。
- 产出：真实项目中的并行 agent 工作流。

### M5：跨平台发布

- macOS、Windows、Linux 构建矩阵。
- 平台通知、终端 shell、路径和信号差异的自动化验证。
- 产出：可分发的 beta 安装包和升级说明。


## 7. 每个功能的闭环

每个功能按以下顺序完成，完成一项再进入下一项：

1. 写需求和可度量验收标准。
2. 写技术设计和状态/事件契约。
3. 先写会失败的测试，并记录测试命令。
4. 实现最小行为，保持改动范围可审查。
5. 运行格式化、静态检查、单元测试和集成测试。
6. 进行故障场景复核，更新文档和变更记录。
7. 提交一个可回滚的 commit，记录下一步和遗留风险。

## 8. 当前执行项

已有项目分组、多会话、日志搜索/导出、独立后台、最终场景、收件箱和 Codex/Claude/OpenCode 结构化接入；Codex/Claude 可信原生续聊与实时内存显示已有代码和有限实测。三平台实际隔离包生命周期检查已通过；实时键鼠/缩放/快速切换/Cmd+Q 联合流程、Windows/Linux 通知点击及正式签名分发仍有缺口。详细证据、CLI 降级条件及未实现项见 [当前能力清单](yam-capability-matrix.md)，不以早期 M0–M4 切片代替全部里程碑验收。
