# YAM 模型接入与会话连续性实现方案

作者：Jeff.Liu。日期：2026-10-16。

## 目标与执行顺序

先打通 DeepSeek + Codex CLI 的隔离启动、历史保存、关闭后原生续聊，并验证官方 Codex 的登录环境保持独立；随后补齐 Claude Code、Gemini CLI，以及 Gemini 经 Claude CLI 和兼容网关的选择。每一步先运行失败测试，再做最小实现、回归与复核。此方案已获同会话“先写方案，再闭环逐步修复”的执行授权。

当前基础为 `8fb2cb00c32a5ae72b48f0d04776eec1420734ab` 加当前未提交内容。已有终端、后台 owner、JSON 历史、原生 ID、日志与模板继续复用。基线 Source Receipt v2 及各切片在同名 JSON 计划中冻结。

## 选择的实现方式

### 供应商与执行器

在现有 `AgentLaunch` 中增加向后兼容、可选的连接配置快照。`adapter` 始终表示真正执行的 CLI；供应商、模型、端点及凭据引用独立保存。旧记录没有快照时沿用原有原生 CLI 行为。

| 来源 | 默认 CLI | 可选方式 |
| --- | --- | --- |
| Codex 订阅 | codex | 原生登录环境 |
| Claude Code | claude | 显式 API / 兼容网关 |
| Gemini | gemini | claude + Anthropic 兼容网关 |
| DeepSeek | codex | Responses 直连优先，也可使用兼容网关 |

DeepSeek 默认端点为 `https://api.deepseek.com`，模型字段可编辑。直接 API 的密钥来自用户指定的环境变量，默认 `DEEPSEEK_API_KEY`；历史、模板、应用偏好与项目文件只保存变量名，不保存其值。通过本地网关接入时，上游密钥由网关持有。第一版不引入新的密钥库、依赖或自研协议代理。

备选是完全依赖 CC Switch / Magpie 改写全局 CLI 配置。该方式实现更少，但无法满足同时保留官方订阅环境和稳定的每会话路由，因此本方案采用 YAM 的进程级配置隔离，并允许可选网关端点。

### 隔离边界

- 第三方 Codex 使用 YAM 应用私有目录下的独立 `CODEX_HOME`；路径由经过验证的连接快照稳定确定，以便重启后找到同一原生存储。
- 独立配置仅写连接字段，不复制官方 `auth.json`、订阅 token、全局配置、插件或历史。
- 凭据只在 owner 解析后传给该次子进程。清理冲突的继承认证 / 端点变量，明确选用 API 认证；缺凭据或配置冲突在创建任务前失败。
- 启动、能力探测、`config/read`、`thread/read` 与 resume 使用同一个准备后的命令环境，禁止探测官方配置而实际运行第三方配置。
- 现有项目环境配置也要保存其变量引用，续聊重新解析；只保存引用，不将解析后的值落盘。
- 端点只接受 HTTPS；本地兼容网关允许 loopback HTTP。拒绝 URL 中的账号、密码、query、fragment、控制字符与无效模型 / 变量名。
- 配置目录和文件使用项目已有的私有文件防护；拒绝符号链接、已有内容冲突及目录替换，不用覆盖已有认证文件实现切换。
- 第三方失败不自动改用订阅，不隐式更换供应商或重新开始会话。

### 历史与续聊

历史保留连接快照、凭据变量引用、工作目录和可信原生 ID。继续对话由 owner 从历史重建连接配置，前端只发送历史 ID，不能覆盖供应商、目录或 native ID。

原生对话与 PTY 执行记录分开：一次 Continue 可以产生新执行记录，但必须关联原对话，沿用原生 ID；历史列表避免把每次进程重启显示成互不相关的对话。原执行日志继续保留。

默认官方 Codex 保持原有 resume 校验。受管第三方配置只允许与连接快照兼容的安全参数；不通过放开任意 `-c`、`--profile`、远程地址或身份覆盖选项实现续聊。旧的、不具备可信身份的自定义命令仍不能伪装为可续聊会话。

Gemini 使用其原生 `--resume` 能力。优先由显式 UUID 建立会话身份，并验证原生存储和工作目录；不根据终端文字猜测身份。Claude 继续复用现有原生 UUID 校验。

### 用户界面与复用

复用启动表单、个人模板、项目设置、历史列表和 Continue。增加明确的模型来源、CLI、模型、端点及凭据来源字段；选择来源时给出上表默认 CLI。普通用户不必手写 provider TOML 或启动命令。

第一轮保留当前终端交互。统一消息式聊天界面可复用连接和原生身份基础，作为后续独立切片；它不作为本轮配置隔离、历史与续聊通过的替代证据。

Magpie 作为可选标准端点接入，不作为必装依赖，不调用其全局 Connect / Switch 去替换官方环境。参考 CC Switch 的原生历史阅读与 CLI 格式适配，参考 Cherry 的稳定对话 / 消息与原生身份分离；不迁移或改写用户官方历史。

## 行为与验证矩阵

| 输入 / 状态 | 预期行为 | 副作用与验证 |
| --- | --- | --- |
| 旧官方 Codex 启动 / Continue | 原来的 CLI 与官方环境 | 命令构造和回归测试确认无第三方环境覆盖 |
| DeepSeek 配置合法且凭据可用 | codex 使用独立配置和 Responses 端点 | Rust 实际命令 / 临时文件测试；官方目录哨兵逐字节不变 |
| 缺凭据、非法 URL、冲突目录 | 创建任务前明确失败 | 不生成历史，不写官方目录，不输出密钥 |
| 保存模板 / 重开历史 | 保留模型、端点和变量引用 | JSON 重读测试；断言无明文凭据 |
| 结束后 Continue | 同一原生对话和同一连接快照 | 实际 owner 共用 seam、前后端断言、native ID 校验 |
| 续聊配置缺失或原生 ID 不存在 | 报错，无新对话 / 订阅回退 | 错误路径回归，校验调用与历史没有新增 |
| 官方与第三方同时运行 | 路由、凭据、历史各归其所属环境 | 可控端点加官方目录哨兵；交叉会话测试 |
| Gemini 选择默认 / 可选 CLI | gemini / claude | 参数、resume、模板和实际回调测试 |
| 网关停用 | 该会话明确失败 | 禁止隐式改为官方订阅 |

## 有限实施步骤

1. **T1：DeepSeek 隔离启动。** 增加连接快照和校验，准备独立 Codex 环境，接通表单 / 模板 / 项目配置与历史持久化。验收为用户能配置并启动隔离的 DeepSeek 会话，且官方文件不变。
2. **T2：重启续聊。** 将探测与 resume 绑定同一配置，恢复项目环境引用并关联原对话。验收为重开历史后仍使用同一 native ID、目录、供应商及模型，缺失时明确失败。
3. **T3：Claude / Gemini。** 复用连接准备与历史机制，补 Gemini CLI 和 Gemini 经 Claude CLI 的显式网关映射。验收为各组合实际命令和原生存储身份正确，不混用认证环境。
4. **T4：集成验证和风险复核。** 用独立临时目录、可控本地端点和真实已安装 CLI 验证首次请求、停进程、重启及 resume；执行相关前后端测试、标准 build、全范围复核，修复同范围缺陷。

每一步的开始、结果、验证与缺口会同步到原生计划面板和 commentary。未授权提交、发布、升级 CLI 或安装三方软件。

## 完成证据与边界

先通过不消耗付费额度的确定性回归和真实 CLI + 本地端点验证。真实 DeepSeek / Claude / Gemini API 往返需要用户配置可用凭据；没有实际结果时保留“未验收”，不把模拟服务结果改称供应商实测。

最小实体验收：在 DeepSeek 对话中记录一个临时代号，结束进程并重启，继续历史后核对同一原生 ID、原路由和上下文；同时打开官方 Codex，确认其仍处于原有订阅环境。供应商不可达、Key 无效、原历史缺失也必须得到可理解的错误。

## 实施结果（2026-10-16）

T1–T3 已实现；T4 的真实 CLI 本地检查已覆盖 DeepSeek/Codex、Gemini/Claude 兼容网关、Gemini/Gemini。检查通过独立临时仓库和 loopback 协议夹具运行：首次请求、进程结束、历史 JSON 重开、同一原生 UUID 的续聊、请求中携带前文、独立测试凭据和官方目录哨兵逐字不变。所用 CLI 为本机已安装版本，没有升级或安装。

初次检查确实暴露了 Claude 项目 `settings.json` 中 API 环境变量覆盖进程连接的问题。现在受管 Claude / Gemini 会话会在启动和落历史前检查项目认证覆盖；正常权限设置继续交给 CLI。冲突时明确失败，用户可移除项目中的 API/auth 覆盖或选择原生登录。已添加正常、冲突、非法配置和环境引用回归；实际删除保护分支的 mutation 检查被回归断言检出。

前端启动表单 **Model source** 提供 Codex 订阅、Claude / Gemini 原生登录、DeepSeek、Claude API、Gemini API 与 Gemini 经 Claude 网关。CLI 字段显示真正的执行器；模型、URL 和变量名可编辑。选本地网关时，密钥变量名可留空。来源与 CLI 不兼容会在启动前报错。

项目 `env` 引用随启动快照保存，续聊由后台重新解析；当前会话探测和 CLI 共用解析后的环境。只修改变量值即可轮换密钥。变量必须存在于后台 owner 的环境中；仅关闭再打开窗口不会替换仍在运行的 owner 环境，需完整退出 YAM 后从拥有该变量的环境重新启动。任何凭据缺失都会报错，不回退为订阅或新对话。

同一会话的 Continue 会在历史中显示最新运行；**Previous runs** 可打开旧运行日志。旧 JSON 无新增字段仍可读取。Gemini 原生校验以 0.64 的项目目录标记和 JSON/JSONL 元数据为依据；缺少可验证目录身份的旧格式会明确拒绝，保留原文件。

真实 DeepSeek / Claude / Gemini 服务未使用付费凭据进行调用；真实 GUI 的信任交互和交互式 hook 到 owner 的完整链路仍需在运行中的桌面程序验收。真实 CLI 检查采用 headless 参数驱动同一命令构造与原生存储，不将它标称为 GUI 或供应商实测。Converge coverage 适配器的未覆盖状态保持不变；最终测试和独立复核回执将另行记录。


独立 spec 复核后的修正：后台 RPC 白名单现已显式接受并校验 `provider` / `env_refs`；受管启动、项目启动和 Continue 请求带内部能力标记，前端创建前还会检查本机程序能力。旧程序或旧 owner 明确拒绝该请求，不自动启动替代进程。显式项目认证环境引用出现冲突时会报错，指定密钥变量的正常映射仍可使用；原生 Claude/Gemini 的文件校验按实际子进程 `HOME` / `USERPROFILE` 和 CLI 专属目录引用定位。Codex 项目 TOML 的路由继续由 CLI 高优先级覆盖固定，真实 CLI 已验证该优先级；未增加 TOML 解析器。

质量复核发现并修正归档恢复后的代表运行选择：历史列表按原始运行时间和既有 session ID 的数值时间/计数器选择最新运行，避免恢复旧归档时把运行中的新执行隐藏为 Previous runs。不新增历史字段；同秒、同毫秒及十六进制计数器边界、恢复最新运行和旧日志保留均纳入回归。


## 桌面实体验收（2026-10-16）

本轮使用单独应用标识 `com.yam.provider-desktop-validation-20261016` 构建本机 macOS 桌面包，通过真实界面操作已安装的 Codex CLI 0.162.1。请求仅进入 loopback Responses 夹具，不转发供应商；用户已明确跳过真实 API 凭据和供应商往返。

实际验证链路：表单 DeepSeek 默认映射为 Codex；缺少凭据时在落历史前报错；保存本地端点模板后启动 CLI；在独立目录中完成 CLI 自身的目录和 hook 信任交互；收到真实 SessionStart / response hook；停止进程并完整退出 GUI 和后台 owner；重新启动桌面、恢复模板和历史、点击 Continue。重启后的 owner 是新实例，续聊沿用同一原生 UUID `01a14454-36e5-7cc1-8f19-4249bd7e5270` 和连接快照，原始 prompt 没有重放；只询问先前代号时，真实 CLI 将已有上下文带入本地请求并得到原代号。Previous runs 可打开旧执行日志。

验收发现并按红灯回归、修复、绿灯及重新构建闭环了三个问题：

1. Codex 会在独立配置中追加目录信任、hook 信任和 TUI 元数据，原来的全文相等检查会在下次启动时误报配置变更。现在保留固定连接配置前缀，仅接受限定的原生元数据表追加；改路由、认证或其他配置表、非法 UTF-8、超大文件和符号链接仍被拒绝，不覆写 CLI 元数据。
2. Previous runs 作为 flex 同行元素会把会话标题挤成极窄列。现在独占下一行，实体验证标题和历史展开正常。
3. 新建会话过早关闭对话框，会因旧终端的焦点恢复取消新终端挂接。现在先完成挂接，再关闭对话框，并仅在新视图仍选中且就绪时聚焦。重建后的桌面包实测自动选中新会话，Terminal input 获得焦点并完成请求。

验收前后逐字节哈希和修改时间比较确认 `~/.codex/config.toml` 与 `~/.codex/auth.json` 没有变化，`codex login status` 退出码 0 且仍报告 ChatGPT 登录。没有向官方订阅发起付费往返，因此结论限定为官方配置和登录状态未受影响。独立测试应用已完整退出；保留本地验收历史供追溯。

本轮证据目录为 `/tmp/yam-desktop-provider-acceptance-20261016`，包含桌面重启断言、本地请求回执、官方文件前后哈希、红绿测试日志、最终源码绑定回归与桌面包指纹。真实 DeepSeek 服务、其他供应商桌面交互及 Converge coverage 适配器缺口仍不标为已验收。


独立质量复核追加的边界修正：终端慢速挂接期间，如果用户已关闭启动框并转到搜索输入，挂接完成不得抢回焦点。新增直接终端、Continue、关闭启动框三种延迟帧回归，均先复现失败；现在仅当启动框仍打开且仍持有输入焦点时，在关闭后聚焦新终端。一般启动继续遵循 `openHistory` 已有的焦点意图保护。
